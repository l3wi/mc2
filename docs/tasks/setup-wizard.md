# Task: `mc2 setup` — interactive setup wizard (server / client trees)

Status: **IMPLEMENTED — 2026-08-08**
Date: 2026-08-08

## Context

Remote management (local/remote client modes, self-ingress route) is shipped,
but the operator still must assemble the moving parts by hand: server flags,
the API token, a Traefik static config, DNS/ports, then a client context. The
user wants an **interactive wizard** to replace that assembly:

- **Server tree** (run on the VPS): pick the server options you want — including
  writing a ready-to-run default `traefik.static.yml` once — then print the
  exact commands to finish the setup (start server → start Traefik → DNS/ports),
  and hand off to the client tree.
- **Client tree** (run on your laptop): answer where to connect + the API key,
  get a context saved and made current, and verify against the live server.

The wizard only *writes config and prints instructions*; it never starts the
server or Traefik (consistent with "one process, no daemon", BYO Traefik).

## Feasibility verdict: HIGH

- Everything the wizard touches already exists: `context set/use/ls`
  (`context.rs`), the self-route + `--public-hostname`, and the Traefik
  dynamic-config renderer. The wizard adds *scaffolding*, not new machinery.
- Default `traefik.static.yml` is operator-owned after generation (mc2 never
  rewrites it), matching the current BYO static-config story
  (`examples/04-http-ingress/traefik.static.yml`).

## Design

### Command surface

```text
mc2 setup              # interactive: "What are you setting up?" → Server / Client
mc2 setup server       # jump straight to the server tree (non-interactive flags usable)
mc2 setup client       # jump straight to the client tree
```

Bare `mc2 setup` asks the tree question. `server` / `client` subcommands exist
so the trees are reachable non-interactively in scripts and tests.

### Interactive prompts (MVP)

`dialoguer` (arrow-key menus) behind a thin `prompt.rs` wrapper. All prompt
helpers return `anyhow::Result`; core plan/logic functions stay pure so they're
unit-tested without a pty. Non-tty stdin → friendly "run in a terminal" error.

**Server tree** (`ServerPlan`):

| Prompt | Default |
| --- | --- |
| Bind address | `127.0.0.1:7443` |
| Data dir | `~/.mc2` |
| Protect API with a key? | yes (else `--no-auth`) |
| Public hostname (empty = local-only) | e.g. `mc2.example.com` |
| TLS cert resolver | `le` |
| Ingress config dir | `~/.mc2/ingress` |
| Write default `traefik.static.yml`? | yes (when hostname set) |
| ACME email | required if writing Traefik config |

Output: the generated `mc2 server …` command, the path to the written static
config, and a numbered **"finish setup"** checklist (run server → token prints
once → run `traefik --configFile …` → DNS + open 80/443 → run `mc2 setup`
locally and pick Client).

**Client tree** (`ClientPlan`):

| Prompt | Default |
| --- | --- |
| Context name | `prod` |
| API URL | `https://<hostname>` |
| API token | masked input |
| Set as current + verify? | yes |

Output: writes the context (reuses `context.rs`), prints the context row, and
(optional) a live `mc2 status` check.

### Default `traefik.static.yml` (written once, never clobbered)

```yaml
# Generated by MC2 — operator-owned after this point.
entryPoints:
  web:        { address: ":80" }
  websecure:  { address: ":443" }
certificatesResolvers:
  le:
    acme:
      email: <email>
      storage: <ingress parent>/acme.json
      httpChallenge: { entryPoint: web }
providers:
  file:
    directory: <ingress-dir>/traefik
    watch: true
```

Written to `<ingress parent>/traefik.static.yml`; if the file already exists,
mc2 skips it and points at it (no clobber). Ports 80/443, `websecure` for the
self-route, `le` resolver — all aligned with what mc2's dynamic config emits.

## Out of scope (deliberate)

- Starting/supervising the server or Traefik, systemd units, upgrades.
- Managing the ACME/cert lifecycle (still Traefik's job).
- Editing *existing* Traefik static configs (only the default is scaffolded).

## Risks

- **Prompt UX without a pty**: `mc2 setup` in a non-interactive shell would
  hang on stdin. Mitigated: the `server`/`client` subcommands and all core
  logic stay pure/testable; the top-level wizard degrades to a clear "no tty"
  error if stdin isn't a terminal.
- **Static-config divergence**: mc2 only scaffolds once and never rewrites —
  documented in the generated file header.

## Acceptance criteria

- [ ] `mc2 setup` walks two trees; `mc2 setup server` / `mc2 setup client`
      reach each non-interactively.
- [ ] Server tree renders a runnable `mc2 server …` command incl. auth +
      self-ingress flags; prints the finish-setup checklist.
- [ ] Default `traefik.static.yml` written once under the ingress parent
      (no clobber), aligned with mc2's dynamic output (`web`/`websecure`,
      `le` resolver, file provider on `<ingress-dir>/traefik`).
- [ ] Client tree upserts a context, sets it current, and optionally verifies
      via `mc2 status`.
- [ ] Unit tests cover command rendering, static-config write/no-clobber, and
      client apply; `just check` green.

## Implementation notes (2026-08-08)

### Decisions

1. **`dialoguer` arrow-key menus** (user choice) behind a thin `prompt.rs`
   wrapper; core plan/logic functions stay pure and unit-tested.
2. **Interactive-only** server tree (MVP); logic is pure so non-interactive
   flags can be added later.
3. Static config path: `<ingress-dir parent>/traefik.static.yml` (e.g.
   `~/.mc2/traefik.static.yml` when ingress dir is `~/.mc2/ingress`); ACME
   storage `<same parent>/acme.json`. Written once; never clobbered.

### What shipped

- **`prompt.rs`** — thin dialoguer wrappers (`select`/`input`/`confirm`/`secret`),
  `is_terminal()` + `ensure_tty()` guard.
- **`setup.rs`** — `ServerPlan`/`ClientPlan`; `render_server_command` (shell-quoted
  `mc2 server …` line incl. auth + self-ingress flags); `write_traefik_static`
  (returns `(path, wrote)`, no clobber); `apply_client` (context upsert +
  current via new `ClientConfig::set_context`/`set_current`); `verify_connection`
  (live status check); `run`/`run_server_wizard`/`run_client_wizard`; server
  checklist printing.
- **`context.rs`** — added `ClientConfig::set_context` (upsert, token replaced
  only when non-empty) + `set_current`; `context_set`/`context_use` in main.rs
  refactored onto them (no behavior change). Centralized a shared test
  `HOME_LOCK`/`with_home` (pub(crate), `#[cfg(test)]`) used by both `context`
  and `setup` test modules — fixes a concurrent-HOME race between the two
  modules.
- **`main.rs`** — `setup` command: bare `mc2 setup` selects the tree;
  `mc2 setup server|client` jump straight in.
- **Deps** — `dialoguer = "0.11"` added to `mc2`.
- **Tests** — unit: server-command rendering (auth/self-ingress on; local-only
  + `--no-auth`), static-config write + no-clobber, client apply roundtrip;
  smoke: `setup --help` lists both trees, non-TTY stdin fails with the
  "interactive" message.
- **Docs** — CHANGELOG entry, README table row + wizard blurb, quickstart
  "Setup wizard" section.

### Verified interactively (pty via `expect`)

- Server tree: defaults accepted with `Enter`, hostname/email entered; printed
  the runnable command + 4-step checklist and wrote `traefik.static.yml`
  (entryPoints 80/443, `le` resolver + httpChallenge, file provider on
  `<ingress>/traefik`).
- Client tree: context `prod` saved + made current (config 0600, token stored,
  masked during input); optional verify fails gracefully (warning) when the
  endpoint is unreachable and still completes.
- `just check` green.

### Known gaps / follow-ups

- No non-interactive flags for the server tree yet (scripted installs) — logic
  is already pure.
- No systemd unit generation (deferred).
- `mc2 setup` needs a real TTY; CI only covers `--help` + the non-TTY guard.
