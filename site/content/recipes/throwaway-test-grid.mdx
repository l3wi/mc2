---
title: Throwaway test grid
description: Bring up N identical microVMs, run a check on every one, and throw them away — keeping a cache volume between runs if you want.
---

## What you'll build

Four identical runner microVMs and one cache service. Every runner fetches
from the cache over the stack's network; the cache keeps its files in a
volume, so it survives `mc2 down` and is ready for the next run.

```text
 runner/0 ─┐
 runner/1 ─┤
 runner/2 ─┼──► cache:18400 ──► cache/0 ──► volume "cache"
 runner/3 ─┘                                (kept across runs)
```

## The stack

Save as `test-grid.yaml`:

```yaml
name: test-grid
volumes:
  cache:
    size: 1GiB
services:
  cache:
    image: python:3.12-alpine
    mem_limit: 256m
    expose: [18400]
    volumes:
      - name: cache
        target: /cache
    restart: always
    command: ["/bin/sh", "-c", "mkdir -p /cache/www && cd /cache/www && exec python -m http.server 18400"]
  runner:
    image: alpine:3.20
    scale: 4
    mem_limit: 256m
```

- `runner` is the grid: four microVMs, `restart: no` (the default), so a
  throwaway grid never resurrects itself.
- `cache` serves the volume's files over HTTP. Runners read them; there's no
  write API in this example — the cache service is the volume's only writer,
  which keeps the runners from racing on a shared directory.
- `size: 1GiB` caps the cache and counts toward any `--limit-disk-mib`
  budget.

## Run it

<Steps>

<Step title="Bring up the grid">

```bash
mc2 up -f test-grid.yaml
mc2 ps --stack test-grid      # wait for cache/0 and runner/0..3 to be Running
```

</Step>

<Step title="Seed the cache">

```bash
mc2 exec test-grid/cache/0 /bin/sh -c 'echo PERSISTED > /cache/www/persist.txt'
```

</Step>

<Step title="Run the suite on every runner">

```bash
for i in 0 1 2 3; do
  mc2 exec test-grid/runner/$i /bin/sh -c \
    'test "$(wget -qO- http://cache:18400/persist.txt)" = PERSISTED && echo PASS' || exit 1
done
# PASS
# PASS
# PASS
# PASS
```

`mc2 exec` returns the guest's exit code, so the loop stops at the first
failing runner. To run a real suite, bake it and its dependencies into the
runner image, then swap in its command.

</Step>

<Step title="Throw the grid away, keep the cache">

```bash
mc2 down test-grid
mc2 up -f test-grid.yaml        # the next run, immediately
# after the instances are Running:
mc2 exec test-grid/runner/2 wget -qO- http://cache:18400/persist.txt
# PERSISTED
```

The startup command never writes `persist.txt`, so seeing it proves the
volume survived.

</Step>

<Step title="Throw everything away">

```bash
mc2 down test-grid --volumes
```

Choose one: `mc2 down test-grid` keeps the cache; `--volumes` deletes it
too. `--volumes` needs the stack to exist, so if you already ran a plain
`down`, re-apply first.

</Step>

</Steps>

## Notes

- **Fresh VMs every run.** Each `up` after a `down` boots new microVMs from
  the image; nothing but the volume carries over.
- **Sizing.** Four runners × `mem_limit` plus the cache must fit the host
  (and any `--limit-*` budget), or `mc2 up` refuses the stack.
- **Parallel grids.** Give each grid its own stack name and its own `expose`
  port — exposed ports are unique on the server.
