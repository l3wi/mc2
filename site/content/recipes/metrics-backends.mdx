## What you'll build

Send MC2 control-plane metrics to an OpenTelemetry collector with
`MC2_OTLP_ENDPOINT`, then point the microsandbox metrics sidecar (msb-metrics)
at the same collector so control-plane and sandbox metrics land in one
pipeline.

<Warning title="Under development">
UNDER DEVELOPMENT: the collector configuration is retained here, but this
example does not yet include a complete start-and-verify workflow.
</Warning>

## The stack

This recipe's "stack" is the OTLP pipeline. MC2 exports control-plane metrics
(`mc2.server.*`, `mc2.node.*`) when `MC2_OTLP_ENDPOINT` (or
`OTEL_EXPORTER_OTLP_ENDPOINT`) is set. The collector config lives in the
examples tree at `examples/90-advanced/observability/collector-config.yaml`:

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 5s
  resource:
    attributes:
      - key: collector
        value: mc2-lab
        action: upsert

exporters:
  debug:
    verbosity: basic
  prometheus:
    endpoint: 0.0.0.0:8889
    namespace: mc2_lab

service:
  pipelines:
    metrics:
      receivers: [otlp]
      processors: [batch, resource]
      exporters: [debug, prometheus]
```

The collector accepts OTLP on gRPC `:4317` and HTTP `:4318`, prints metrics to
its debug exporter, and re-exports a Prometheus scrape endpoint on `:8889`.

## Run it

<Steps>
<Step title="Start the collector">

```bash
otelcol --config examples/90-advanced/observability/collector-config.yaml
```

Or with Docker:

```bash
docker run --rm -p 4317:4317 -p 4318:4318 \
  -v "$PWD/examples/90-advanced/observability/collector-config.yaml:/etc/otelcol/config.yaml" \
  otel/opentelemetry-collector:latest
```

</Step>
<Step title="Point MC2 at the collector">

Set the endpoint before booting the server:

```bash
export MC2_OTLP_ENDPOINT=http://127.0.0.1:4317
mc2 server --no-auth
```

`MC2_OTLP_ENDPOINT` and `OTEL_EXPORTER_OTLP_ENDPOINT` are both honored.

</Step>
<Step title="Point the sandbox sidecar at the same collector">

Sandbox CPU/mem/net stay on msb-metrics — point that sidecar at the same
collector if you want one pipeline. The resource processor tags both with
`collector=mc2-lab`; the attributes include `service.name: mc2-server |
msb-metrics`.

</Step>
</Steps>

## Verify

Confirm the endpoint is picked up:

```bash
mc2 version
```

reports `otlp endpoint: http://127.0.0.1:4317`. The server exports control-plane
metrics: `mc2.server.*` (`applies`, `schedule_binds`, `instances`, …) and
`mc2.node.*` (`reconciles`, `reconcile_errors`, …).

Check the collector's Prometheus export:

```bash
curl -s http://127.0.0.1:8889/metrics | grep mc2_
```

## Notes

- For Grafana, add a Prometheus data source that scrapes the collector's
  endpoint (`http://<collector-host>:8889/metrics`), namespace `mc2_lab`.
- MC2 exports control-plane metrics only; sandbox CPU/mem/net live on the
  msb-metrics sidecar. Pointing both at one collector gives you a unified
  view.
- The example is `UNDER DEVELOPMENT` — the collector config exists, but there
  is no complete start-and-verify workflow yet. Treat this recipe as a lab
  setup.
- Start the server after setting `MC2_OTLP_ENDPOINT`; the endpoint is read at
  process startup.
