## What you'll build

An OpenTelemetry collector that receives MC2's metrics over OTLP and
re-exports them for Prometheus, which Grafana can then chart.

```text
 mc2 server ──OTLP :4317──► collector ──:8889──► Prometheus ──► Grafana
                            (debug log)        (scrapes)      (queries)
```

MC2 exports its own metrics: applies, reconcile passes, instance counts by
phase, and per-instance disk use. Per-sandbox CPU, memory, and network come
from microsandbox's own metrics component, configured separately (see
[Observability](/documentation/concepts/observability)).

## The collector config

Save as `collector-config.yaml` (the same file is in the repository at
`examples/90-advanced/observability/collector-config.yaml`):

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 5s
  resource:
    attributes:
      - key: collector
        value: mc2-lab
        action: upsert

exporters:
  debug:
    verbosity: basic
  prometheus:
    endpoint: 0.0.0.0:8889
    namespace: mc2_lab

service:
  pipelines:
    metrics:
      receivers: [otlp]
      processors: [batch, resource]
      exporters: [debug, prometheus]
```

## Run it

<Steps>

<Step title="Start the collector">

With Docker, publishing only on loopback:

```bash
docker run --rm --name mc2-otel \
  -p 127.0.0.1:4317:4317 -p 127.0.0.1:4318:4318 -p 127.0.0.1:8889:8889 \
  -v "$PWD/collector-config.yaml:/etc/otelcol-contrib/config.yaml:ro" \
  otel/opentelemetry-collector-contrib:latest
```

Or natively: `otelcol-contrib --config ./collector-config.yaml`. (The
`prometheus` exporter is in the *contrib* distribution.)

</Step>

<Step title="Start MC2 with the endpoint">

The endpoint is read once at startup, so restart the server with it set:

```bash
export MC2_OTLP_ENDPOINT=http://127.0.0.1:4317
mc2 server
```

The log should show:

```text
INFO mc2_metrics: OTLP metrics export enabled service="mc2-server" endpoint=http://127.0.0.1:4317
```

</Step>

<Step title="Generate some activity">

Apply any stack, e.g. `hello.yaml` from the
[Quickstart](/documentation/quickstart). Metrics are exported every 15 s.

</Step>

<Step title="Check the collector">

```bash
curl -s http://127.0.0.1:8889/metrics | grep '^mc2_lab' | cut -d'{' -f1 | sort -u
```

```text
mc2_lab_mc2_instance_disk_limit_mib
mc2_lab_mc2_instance_disk_used_mib
mc2_lab_mc2_node_reconciles_total
mc2_lab_mc2_server_applies_total
mc2_lab_mc2_server_instances
mc2_lab_mc2_server_nodes_ready
mc2_lab_mc2_server_nodes_total
mc2_lab_mc2_server_schedule_binds_total
```

`mc2_lab_mc2_node_reconcile_errors_total` appears once a pass has failed.
`mc2_lab_mc2_server_instances` carries a `phase` label; the disk gauges
carry `instance` and `target` (`root-disk` or `volume:<name>`).

</Step>

</Steps>

## Prometheus and Grafana

The collector's `:8889/metrics` is a **scrape target**, not something
Grafana can query directly. Point Prometheus at it:

```yaml
# prometheus.yml
scrape_configs:
  - job_name: mc2
    static_configs:
      - targets: ["127.0.0.1:8889"]
```

Then add Prometheus (e.g. `http://localhost:9090`) as a data source in
Grafana. Useful queries:

```text
rate(mc2_lab_mc2_node_reconciles_total[5m])            reconcile throughput
increase(mc2_lab_mc2_node_reconcile_errors_total[1h])  failed passes
sum by (phase) (mc2_lab_mc2_server_instances)          instances per phase
mc2_lab_mc2_instance_disk_used_mib
  / mc2_lab_mc2_instance_disk_limit_mib                disk fill ratio
```

## Notes

- **Environment only.** MC2 reads `MC2_OTLP_ENDPOINT`, then
  `OTEL_EXPORTER_OTLP_ENDPOINT`, then `OTEL_EXPORTER_OTLP_METRICS_ENDPOINT`;
  there's no command-line flag. The exporter speaks OTLP over gRPC.
- **`mc2 version` isn't proof.** It shows the endpoint set in *your* shell,
  not what the running server uses; check the server log line above.
- **Alert on disk.** A fill ratio near 1 means writes are about to fail with
  `No space left on device`.
- **Labels.** Series arrive with `job="mc2-server"` (from the OTLP resource's
  `service.name`), plus the collector's `collector="mc2-lab"` attribute.
