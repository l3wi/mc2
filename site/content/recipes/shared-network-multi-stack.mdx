---
title: Shared networks across stacks
description: Let services in separate stacks talk over one server-wide named network, while each stack keeps its own lifecycle.
---

## What you'll build

Two stacks with separate lifecycles — say, a shared `api` and an app that
uses it — that reach each other over a named network. Either can be
re-applied or torn down without touching the other.

```text
 stack "platform"                              stack "app"
 ┌───────────────────┐    network "shared"    ┌───────────────────┐
 │ api  expose 18500 │◄──────────────────────│ probe             │
 └───────────────────┘  api.shared.svc.mc2   └───────────────────┘
```

## The stacks

`platform.yaml`:

```yaml
name: platform
networks:
  shared:
    mode: mediated
services:
  api:
    image: python:3.12-alpine
    networks: [shared]
    expose: [18500]
    restart: always
    command: ["/bin/sh", "-c", "mkdir -p /tmp/www && echo FROM_PLATFORM > /tmp/www/index.html && cd /tmp/www && exec python -m http.server 18500"]
```

`app.yaml`:

```yaml
name: app
networks:
  shared:
    mode: mediated
services:
  probe:
    image: alpine:3.20
    networks: [shared]
```

Both join `shared`. The network exists once on the server; declaring it in
each file just states its mode. `probe` needs no `expose` to be a client.

## Run it

<Steps>

<Step title="Apply both stacks">

```bash
mc2 up -f platform.yaml
mc2 up -f app.yaml
mc2 ps --stack platform && mc2 ps --stack app   # wait for both Running
```

</Step>

<Step title="Call across stacks">

```bash
mc2 exec app/probe/0 wget -qO- http://api.shared.svc.mc2:18500/
# FROM_PLATFORM
```

From another stack, a peer's full name uses the shared network:
`<service>.<network>.svc.mc2`. The short name `api` works too.

</Step>

<Step title="Inspect">

```bash
mc2 network shared            # members from both stacks
mc2 network app/probe/0       # what probe can reach
```

</Step>

<Step title="Change one stack alone">

```bash
mc2 down app                  # platform keeps running
mc2 up -f app.yaml            # app comes back and reconnects
```

</Step>

<Step title="Clean up">

```bash
mc2 down app
mc2 down platform
```

</Step>

</Steps>

## Notes

- **Sharing a network is permission.** Every service on `shared` can reach
  every exposed port on it, from any stack. Use separate named networks for
  separate trust zones.
- **Exposed ports are unique server-wide.** `18500` belongs to
  `platform/api` while that stack exists; `mc2 network` lists the owner of
  every claimed port.
- **Name selection.** Inside `platform`, peers use
  `<service>.platform.svc.mc2`. From another stack sharing several named
  networks with it, MC2 injects one full name, using the first shared network
  alphabetically.
- **One server.** Networks are local to the server in v1.
