---
title: Remote coding agents over SSH
description: Give a coding agent or developer its own microVM with SSH access — locally, then on a remote server through Traefik.
---

## What you'll build

A dev microVM you (or a coding agent) can SSH into, first on your own
machine, then on a remote MC2 server reached through Traefik. SSH is served
by MC2 on the host, so the image needs no `sshd`.

```text
 local:   ssh -p 2222 ──────────────────► 127.0.0.1:2222 (MC2) ──► dev VM
 remote:  ssh -p 2200 server ──► Traefik :2200 ──► 127.0.0.1:2222 ──► dev VM
```

Your private SSH key stays on your machine; only the public key is
registered with the server. Code you upload or edit lives in the microVM.

## The stack

Save as `dev-agents.yaml`:

```yaml
name: dev-agents
volumes:
  work:
    size: 20GiB
services:
  agent:
    image: alpine:3.20
    volumes:
      - name: work
        target: /work           # survives recreates; keep repos here
    ssh:
      enabled: true
      port: 2222
      authorizedKeys: [developer]
```

- No `command`: the VM runs `sleep infinity` and stays up for sessions.
- `/work` is a volume, so checked-out code survives a recreate.
- A fixed `port` is needed for the Traefik step. For several agents, give each
  its own service and port.

## Run it locally

<Steps>

<Step title="Register your key">

```bash
mc2 ssh add-key developer --file ~/.ssh/id_ed25519.pub
```

</Step>

<Step title="Apply and check the endpoint">

```bash
mc2 up -f dev-agents.yaml
mc2 ssh ls          # wait for dev-agents/agent/0 → Open on 127.0.0.1:2222
```

</Step>

<Step title="SSH in">

```bash
ssh -p 2222 root@127.0.0.1
```

SFTP works too (`sftp -P 2222 root@127.0.0.1`), so editors and agents that
sync files over SFTP can use it directly.

</Step>

</Steps>

## Run it on a remote server

Assume a server set up as in
[Manage a remote server](/documentation/guides/manage-a-remote-server), with
Traefik and `--ingress-config-dir ~/.mc2/ingress`.

<Steps>

<Step title="Switch context and register the key there">

```bash
mc2 context use prod
mc2 ssh add-key developer --file ~/.ssh/id_ed25519.pub
```

Keys are stored per server; the one you registered locally doesn't travel.

</Step>

<Step title="Add a TCP route">

Append to `dev-agents.yaml`:

```yaml
ingress:
  tcp:
    - name: agent-ssh
      entryPoint: ssh
      service: agent
```

and give the server's Traefik an `ssh` entry point (then restart Traefik):

```yaml
entryPoints:
  ssh:
    address: ":2200"
```

</Step>

<Step title="Apply and connect">

```bash
mc2 up -f dev-agents.yaml
ssh -p 2200 root@mc2.example.com
```

Allow inbound TCP 2200 on the server's firewall. The route is a
`HostSNI(*)` TCP router, so each SSH entry point serves one backend: for a
second agent, add a second entry point (`:2201`) and route.

</Step>

</Steps>

## Notes

- **Access control is the key list.** Every key in `authorizedKeys` can log
  in as `root`; an empty list (or `ssh: true`) admits every registered key.
- **Sessions don't idle out**, so a quiet agent or `tmux` session stays
  connected. The server caps concurrent sessions (64 total, 16 per
  listener).
- **Per-instance changes.** `mc2 ssh close dev-agents/agent/0` stops the
  endpoint without touching the stack; `mc2 ssh open … --key … --port …`
  reopens it. See [Open SSH](/documentation/guides/open-ssh).
- **Clean up** with `mc2 down dev-agents` (add `--volumes` to delete `/work`)
  and `mc2 ssh rm-key developer`.
