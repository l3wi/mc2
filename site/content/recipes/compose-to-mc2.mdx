## What you'll build

You'll translate a small Compose project (nginx in front, Postgres behind)
into an MC2 stack, validate it, and run both services as microVMs. Most keys
carry over; the differences below are the ones that actually break a naive
copy.

## Before and after

```yaml
# docker-compose.yml (before)
services:
  web:
    image: nginx:1.27
    ports: ["8080:80"]
    depends_on: { db: { condition: service_healthy } }
    restart: on-failure
  db:
    image: postgres:16
    environment: { POSTGRES_PASSWORD: lab }
    healthcheck:
      test: ["CMD", "pg_isready", "-q", "-U", "postgres"]
    volumes: ["pgdata:/var/lib/postgresql/data"]
volumes:
  pgdata: {}
```

```yaml
# myapp/stack.yaml (after) — stack name "myapp" comes from the directory
services:
  web:
    image: nginx:1.27
    command: ["nginx", "-g", "daemon off;"]    # 1. the image CMD isn't run
    ports:
      - "18300:80"                             # 2. binds 127.0.0.1 only
    depends_on:
      db:
        condition: service_healthy
    restart: on-failure
  db:
    image: postgres:16
    command: ["postgres"]                      # 1.
    environment:
      POSTGRES_PASSWORD: lab
    healthcheck:
      test: ["CMD", "pg_isready", "-q", "-U", "postgres"]
      interval: 5s
      timeout: 3s
      retries: 5
      start_period: 30s
    volumes:
      - name: pgdata                           # 3. long form only
        target: /var/lib/postgresql/data
volumes:
  pgdata:
    size: 2GiB                                 # 4. a hard cap (default 10GiB)
```

## The differences that bite

1. **The image's `CMD` doesn't run.** Without `command`, MC2 runs
   `sleep infinity` (the `ENTRYPOINT` still runs). Copy the image's default
   command into `command` — `docker inspect --format '{{json .Config.Cmd}}' <image>`
   shows it.
2. **Published ports bind `127.0.0.1`.** Compose's `"8080:80"` listens on all
   interfaces; MC2's never does. Reach services from outside with
   [ingress](/documentation/guides/publish-with-ingress).
3. **Volume mounts use the long form**, `{name, target}`, referencing a
   top-level volume. `"pgdata:/path"` strings and bind mounts of host paths
   are rejected.
4. **Volumes have a size cap.** `size` (default 10 GiB) is enforced; writing
   past it fails with `No space left on device`.
5. **Services reach each other only on `expose`d ports.** On a Compose
   network any port is reachable; in MC2 the target must list the port under
   `expose`, and an exposed port is unique across the whole server.
6. **Names are lowercase**: `[a-z0-9]([a-z0-9_-]*[a-z0-9])?`, no `.` or
   `--`. Rename `Web` to `web` and `api.v2` to `api-v2`.
7. **Unknown keys are errors**, not warnings — see the table.

## Key mapping

| Compose | MC2 | Notes |
| --- | --- | --- |
| `version` | — | Drop it (rejected). |
| `services.<n>.image` | `image` | Same. |
| `command` | `command` | List or string (split without a shell). **Required** to run the image's usual process. |
| `entrypoint` | — | Not supported; the image's entrypoint always runs. |
| `ports` | `ports` | Short and long forms; always bound to `127.0.0.1`. `scale` > 1 gives each replica its own port. |
| `expose` | `expose` | `[5432]`, `["5432"]`, or `[{port: 5432}]`; TCP only; unique server-wide. **Needed** for peers to connect. |
| `environment` | `environment` | Map or `KEY=VALUE` list. |
| `env_file` | — | Not supported; inline the values or use `secrets`. |
| `healthcheck` | `healthcheck` | Same keys and `CMD` / `CMD-SHELL` / `NONE` forms. |
| `restart` | `restart` | `no`, `on-failure`, `always`, `unless-stopped`. |
| `depends_on` | `depends_on` | List or `condition: service_started \| service_healthy`; first start only. |
| `deploy.replicas` | `scale` | `deploy` itself is rejected. |
| `cpus` | `cpus` | Whole vCPUs, 1–255; `0.5` is rejected. |
| `mem_limit` | `mem_limit` | Same (`512m`, `1g`). Default `512m`. |
| — | `storage_opt.size` | The microVM's root disk, default `4GiB`. |
| `volumes` (service) | `volumes` | `[{name, target}]` only. |
| `volumes` (top-level) | `volumes` | `kind: dir` (default and only kind), `size` (default `10GiB`). |
| `networks` (service) | `networks` | List of names; named networks are server-wide. |
| `networks` (top-level) | `networks` | `mode: mediated` (default and only mode). |
| `labels` | `labels` | Map form only. Metadata; no Traefik label routing. |
| `secrets` | `secrets` | Different model: server-wide store, `{name, env, allowHosts}`. |
| Traefik labels | `ingress` | Top-level `rules` / `tcp`; MC2 writes Traefik config. |
| `build`, `container_name`, `hostname`, `user`, `working_dir`, `extra_hosts` | — | Rejected as unknown keys. Build images beforehand. |

## Run it

<Steps>

<Step title="Validate">

```bash
mc2 config -f myapp/stack.yaml
```

This checks the schema locally and prints what `mc2 up` would send. Unknown
keys fail here with the list of valid ones.

</Step>

<Step title="Bring it up">

```bash
mc2 up -f myapp/stack.yaml
mc2 ps --stack myapp -o json      # repeat
```

`web` stays `Pending` ("depends_on: waiting for db") until Postgres passes
its health check — about 25 s on first boot in testing.

</Step>

<Step title="Verify">

```bash
curl -s http://127.0.0.1:18300/ | grep -o '<title>.*</title>'
# <title>Welcome to nginx!</title>
mc2 volume ls        # pgdata: SIZE 2 GiB, USED ~38 MiB
```

</Step>

<Step title="Clean up">

```bash
mc2 down myapp              # keep pgdata
# or
mc2 down myapp --volumes    # delete pgdata too
```

</Step>

</Steps>

## What stays the same

The mental model: services, replicas, health checks, startup ordering,
restart policies, named volumes, and networks all mean what you expect.
What's new is that MC2 keeps them that way — `mc2 up` records desired state
and the server keeps converging to it. See
[Desired state & reconciliation](/documentation/concepts/desired-state).
