MC2's networking has three security-relevant surfaces: guest-to-guest
(service networks), guest-to-world (egress profiles), and world-to-guest
(host ports and ingress). This page covers each, plus how the CLI talks to a
remote control plane.

```text
 guest ──► peers on its networks ....... default-allow, exposed ports only
 guest ──► internet / LAN / host ...... per egress profile
 world ──► guest ...................... only through ingress you configure
 CLI   ──► mc2 server ................. token; HTTPS required when remote
```

## Guest to guest: service networks

A service lists the ports it serves in `expose`. Every service that shares a
network with it can connect to those ports — no allow-list. Membership **is**
the access control:

- Every service joins its stack's own network, so services in one stack can
  always reach each other's exposed ports.
- Named networks are server-wide; any stack can join one by name.
- Keep workloads that shouldn't talk on separate named networks, or give a
  service `network.profiles: [none]` to cut all networking.

Connections go through a listener MC2 holds on the host (a **splice**) and
are forwarded to one of the owning service's ready replicas.

## Port ownership

Inside a guest every service name resolves to the same gateway address, so
the **port** is what identifies a service. That makes exposed ports unique
across the server:

- `mc2 up` rejects an `expose` port another stack holds (naming it), a port
  MC2 uses itself (the REST port, SSH ports, published host ports, `53`), and
  a port some other host process is already listening on.
- Claims are stored in the database, so two applies can't both win.
- Once a stack's microVMs are being reconciled, MC2 binds and **holds**
  `127.0.0.1:<port>` for as long as the port is exposed and the server runs.
  With no ready replica a client gets *accept-then-close*, and no other
  process can take the port. Removing the `expose` (or the stack) releases
  it; stopping the server releases the listener but keeps the claim.
- One exposed port is one service-wide splice, shared by all replicas;
  `scale` doesn't multiply exposed ports.

## Fail closed

A guest's permission to reach a peer port is fixed when its microVM is
created. If MC2 can't hold the listener for one of those ports, the instance
is reported `Failed` (naming the port) and its microVM isn't created — a
guest must never be allowed to reach a port some other process might own.

On Linux, a non-root server can't bind ports below 1024, so such `expose`
ports are rejected at apply with the fix (`CAP_NET_BIND_SERVICE`, or a higher
port).

## Guest to world: egress profiles

See [Isolation](/security/isolation#egress-profiles). In short: `public`
reaches the internet, `private` reaches your LAN (not just MC2 services),
`host` reaches the host's services including the MC2 API, and `none` reaches
nothing.

## World to guest: host ports and ingress

- **Published ports bind `127.0.0.1`** — never a public interface.
- **The public path is ingress.** A stack's `ingress:` rules become Traefik
  routes that MC2 writes to `--ingress-config-dir`; your Traefik terminates
  TLS and forwards to the loopback port.
- **Ingress input is validated** before it's written: hostnames are exact
  lowercase RFC 1123 names (no port, wildcard, or trailing dot); paths start
  with `/` and contain no whitespace, quotes, backticks, backslashes, or
  control characters; `certResolver`, `entryPoint`, and TCP route names match
  `[A-Za-z0-9_-]+`. Nothing a stack says can inject arbitrary Traefik config.

## CLI to server

The server requires the API token on every `/v1` request, whether you
connect over loopback or remotely — unless it was started with `--no-auth`.

The CLI adds a transport rule: a **remote** URL (anything but `127.0.0.0/8`,
`::1`, or `localhost`) must be `https://`, or the CLI refuses to send the
token. `--allow-insecure-http` or `MC2_ALLOW_INSECURE_HTTP=1` overrides that
— only for throwaway labs or trusted private links.

The server itself speaks plain HTTP on `--bind`. Keep the bind on loopback
and let Traefik terminate TLS (`--public-hostname` writes that route). If you
bind it elsewhere, any client that ignores the CLI's rule can send the token
in the clear.
