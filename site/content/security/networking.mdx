title: Networking
description: Default-allow service networks, unique port claims, loopback host ports, and remote transport rules.

MC2 splits networking into two planes with different security postures.
East–west traffic between services is **default-allow** within a shared
network, Docker-style. North–south traffic in and out of the box is a single,
controlled ingress path — host ports bind loopback and are only exposed
publicly through the ingress catalog. This page covers both, plus the rules
that govern how you reach a remote control plane.

## East–west: default-allow service networks

A service declares `expose` for its internal listeners. Every other service
that shares a **network** reaches it by default over the node loop's L4 splice,
resolved as `<service>.<network>.svc.mc2` DNS.

- Named networks are **server-wide**, so stacks can share one.
- Default-allow within a shared network: if you put a service on the network,
  it can reach every other member.
- A guest's own reach is further bounded by its network profile — see
  [Isolation](/security/isolation).

<Callout type="note">
  Default-allow means membership is the access control. Keep unrelated
  workloads on separate networks, and use `network.profiles: none` when a
  sandbox must not have any network reach at all.
</Callout>

## Port claims are exclusive server-wide

Exposed guest ports are exclusive server-wide and claimed at **apply** time,
for the claim's whole lifetime. A guest resolves every name to the one gateway
IP and msb rewrites `gateway:P` to host `127.0.0.1:P` with no remap, so the
port alone identifies the shared splice — two stacks cannot hold the same
`expose` port. When `scale > 1`, each replica gets a distinct host port (fixed
`8080` becomes `8080, 8081, 8082`; target-only ports get a stable auto host
port).

<Callout type="warning" title="Rejected at apply, not at runtime">
  `mc2 up` returns `400` for an `expose` port another stack already claims
  (naming the owner and suggesting another port), for a port MC2 already takes
  — the REST bind, any SSH listener, any published `ports:` host port, or `53`
  — and for a loopback port a host process is already listening on. The
  listener is then held from apply until the stack is removed, so a client sees
  *accept-then-close* while the service has no running backend, and no host
  process can take the port meanwhile. `mc2 network` prints the owner of every
  claimed port.
</Callout>

## Egress is narrow and fail-closed

A guest's east–west egress is a create-time `Host:tcp:P` rule per reachable
port — no `host` profile, no broad loopback grant (that is exactly why
`network.profiles: [host]` needs the server flag `--allow-host-profile`). A
rule cannot be narrowed after the virtual machine exists, so the node **fails
closed**: if the listener for one of an instance's allowed ports cannot be
bound, that instance is reported `Failed` with the port and cause and its
microVM is never created.

On Linux, `expose` ports below the unprivileged threshold (typically 1024) are
rejected with the fix: grant `CAP_NET_BIND_SERVICE` (`setcap` or systemd
`AmbientCapabilities`), lower `net.ipv4.ip_unprivileged_port_start`, or choose a
higher port. Host ports always bind loopback in any case, so a privileged port
buys reachability from the node itself, never from the network.

## Host ports: loopback only

Published host ports always bind the host's loopback interface. Guests cannot
reach them from inside, and nothing on the box exposes them to the world by
default. The public path in is only what you publish.

## North–south: ingress with TLS

Public HTTP is a deliberate step: declare `ports:` + stack `ingress:` and the
server writes a Traefik file-provider catalog (`--ingress-config-dir`). TLS
termination and certificates are yours to operate — point your Traefik file
provider at the catalog and it terminates TLS for the hostnames you own. MC2
publishes the control plane itself the same way when you set
`--public-hostname`, so a remote install is manageable over TLS.

Ingress inputs are strictly validated before they reach the catalog: hosts must
be exact lowercase RFC 1123 names (no ports, wildcards or trailing dots), paths
must start with `/` and hold no whitespace/quotes/backticks/backslashes/control
characters, and `certResolver`/`entryPoint`/TCP route names are restricted to
`[A-Za-z0-9_-]+`. The catalog is rendered from typed structs, so an invalid or
injected value is rejected at apply rather than written into Traefik's dynamic
config.

## Remote control plane transport

The CLI is a REST client; a remote server is just a URL swap. Two modes,
reported by `mc2 status`:

- **local** — loopback API (`127.0.0.1` / `localhost` / `::1`), token
  optional.
- **remote** — any other host; requires **https + an API key**.

Plaintext `http://` for a remote endpoint is **refused** unless you explicitly
opt in:

```bash
# Refused:
export MC2_API=http://mc2.example.com:7443

# Explicitly allowed (do not use in production):
export MC2_ALLOW_INSECURE_HTTP=1
```

<Callout type="warning" title="Plaintext remote is refused">
  Outside loopback, MC2 refuses `http://` by default. Only
  `--allow-insecure-http` or `MC2_ALLOW_INSECURE_HTTP=1` re-enables it — and
  that defeats the https requirement. Use it for nothing but throwaway labs.
</Callout>
