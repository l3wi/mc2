---
title: Hardening checklist
description: A production checklist for running MC2 — install, host, API access, secrets, networking, and monitoring.
---

Work through this before exposing an MC2 server to real workloads or a
network. Each item maps to a documented MC2 behavior; the
[Security overview](/security/overview) explains the model behind it.

## Install

- [ ] **Install a pinned, verified release.** Download a specific version
      and check its SHA-256 (and, optionally, `gh attestation verify`) as in
      the [Quickstart](/documentation/quickstart). Don't pipe an unpinned
      installer into a shell.
- [ ] **Run as a dedicated user** that owns the data dir and can open
      `/dev/kvm` (the `kvm` group), not as root and not as your login user.
      See the systemd unit in
      [Run the server](/documentation/operations/run-the-server).
- [ ] **Keep the host patched** — kernel, hypervisor, and the OS. The host
      is the trusted ring under every guest.
- [ ] **Vet your images.** MC2 doesn't sign, pin, or scan them.

## API access

- [ ] **Auth on.** Never start a reachable server with `--no-auth`.
- [ ] **Loopback bind.** Keep `--bind` at `127.0.0.1:7443` and publish the
      API through Traefik with `--public-hostname` so TLS is terminated in
      front of it. The server itself speaks plain HTTP.
- [ ] **Save the bootstrap token, then delete `bootstrap-token`** from the
      data dir if the first start wrote one.
- [ ] **HTTPS from clients.** Don't set `--allow-insecure-http` /
      `MC2_ALLOW_INSECURE_HTTP` outside a throwaway lab.
- [ ] **Protect client credentials.** `~/.mc2/config.toml` holds tokens in
      plaintext (mode 0600). In CI, inject `MC2_API_KEY` from a secret store.
- [ ] **Know how to rotate.** `mc2 server token rotate --data-dir <dir>`
      replaces the token instantly; rotate on any suspected leak.

## Secrets and state

- [ ] **Credentials in `mc2 secret set`, never in `environment:`.**
- [ ] **Narrow `allowHosts`** to exactly the hosts that need each secret, and
      only hosts you trust with it — an allowed host can echo it back.
- [ ] **Protect the runtime's copy.** microsandbox keeps running microVMs'
      secret values in plaintext under `~/.microsandbox` (or `$MSB_HOME`) of
      the server's user. Keep that directory private and out of shared
      backups.
- [ ] **Back up `mc2.db` and `secrets.key` together**, with the server
      stopped, and store the backup like a secret: with both files, anyone
      can decrypt your secrets. (The token is only stored as a hash, so the
      backup doesn't contain it.) Include `--secrets-key-path` and
      `--volume-dir` if they're outside the data dir.
- [ ] **Keep the key's permissions strict.** The server refuses a
      world-readable or symlinked `secrets.key`. Fix with `chmod 600`, never
      by replacing the file.
- [ ] **Plan revocation.** Deleting a secret doesn't pull it from running
      microVMs; rotate at the source, remove the reference, then delete it.

## Networking

- [ ] **Separate trust zones with networks.** Services on a shared network
      reach each other's exposed ports by default.
- [ ] **Choose egress deliberately.** `private` reaches your LAN, not just
      MC2 services; use `network.profiles: [none]` for workloads that need no
      network at all.
- [ ] **Leave `--allow-host-profile` off** unless a workload truly needs the
      host's services — it lets guests reach the MC2 API and every published
      port.
- [ ] **Publish only through ingress.** Host ports bind loopback; expose
      what must be public as an `ingress:` rule behind Traefik TLS.
- [ ] **Firewall the host** so only Traefik's ports (and SSH for admins)
      are reachable.

## Listeners

- [ ] **Size the caps.** `--max-connections` (256) and
      `--request-timeout-secs` (60) bound the REST API; `--max-ssh-sessions`
      (64) and `--max-ssh-sessions-per-listener` (16) bound SSH. Behind
      Traefik every client looks like `127.0.0.1`, so rate-limit per client
      at the proxy if you need it.

## Monitor

- [ ] **Readiness:** probe `GET /health` (no token) — `200` while the
      reconcile loop is converging, `503` with a reason when it isn't.
- [ ] **Status:** `mc2 status`, or with curl:

      ```bash
      curl -s -H "Authorization: Bearer $MC2_API_KEY" "$MC2_API/v1/status"
      ```

- [ ] **Metrics:** set `MC2_OTLP_ENDPOINT` and alert on
      `mc2.node.reconcile_errors` and `mc2.instance.disk_used_mib` near
      `mc2.instance.disk_limit_mib`. See
      [Observability](/documentation/concepts/observability).
- [ ] **Logs:** keep the server's logs; internal API errors (500s) are logged
      with their cause, and `environment:`-overrides-secret collisions log a
      warning.
