---
title: Secrets
description: How MC2 stores and injects secrets, where the value exists at each step, and how to rotate, revoke, and recover.
---

A secret is a value you set once on the server and reference by name from
stacks. The guest gets a placeholder; the real value is added to requests
bound for hosts you allow. This page follows the value through the system so
you know exactly where it can be read.

## Where the value lives

```text
 mc2 secret set ──► mc2 server ──► mc2.db          encrypted (secrets.key)
                        │ each reconcile pass: decrypt
                        ▼
                  microsandbox runtime ──► ~/.microsandbox/db   PLAINTEXT
                        │
                        ▼
 guest env:   API_TOKEN=$MSB_API_TOKEN                placeholder only
 guest ──TLS──► allowed host     proxy puts the value in HTTP headers
 guest ──TLS──► any other host   request with the placeholder: blocked
```

| Place | What's there | Who can read it |
| --- | --- | --- |
| `mc2.db` | ciphertext | anyone with the file **and** `secrets.key` |
| `mc2 server` memory | plaintext, briefly, each pass | root / the server's user |
| microsandbox's database (`~/.microsandbox/db` or `$MSB_HOME`) | **plaintext**, while the microVM exists | the server's user |
| the guest | a placeholder (`$MSB_<env>`) | the guest |
| an allowed host | the value, in request headers | that host — which may echo it back |

The runtime's plaintext copy exists because MC2 hands microsandbox the value
itself. Treat that directory like `secrets.key`: owned by the server's user,
not world-readable, and excluded from backups you'd share.

## Encryption

Each value is encrypted with XChaCha20-Poly1305 under the 32-byte
`secrets.key`, with a fresh random 24-byte nonce and the secret's **name** as
associated data — a ciphertext copied onto another name won't decrypt. The
API and CLI only ever return names and timestamps.

## Injection

- The value goes into **HTTP headers** (including Basic auth) of requests to
  an `allowHosts` host. It isn't substituted in URLs or request bodies.
- A request that carries the placeholder to any other host is **blocked and
  logged**; the same request without the placeholder is unaffected.
- `allowHosts` must list at least one host; an empty list is refused.
- An allowed host can return the value in its response, and the proxy
  doesn't redact responses. Allow only hosts you trust with the value.

## `environment:` is not a secret

`environment:` values are plaintext in the stack file and the database, and
visible to every process in the guest. If `environment:` and a secret set the
same variable, `environment:` wins and the secret is dropped (a warning is
logged) — a stray plaintext entry silently disables the secret.

## Rotation

Run `mc2 secret set NAME` with the new value. On the next reconcile pass MC2
sees the value changed and **recreates** every instance that uses it — no
re-apply, and no way to stage a value for later. Plan for the restart; keep
data in volumes.

## Revocation

Deleting a secret doesn't revoke it. `mc2 secret rm NAME` removes it from the
store; consumers are then reported `Failed`, but their existing microVMs —
and the runtime's copy of the value — remain. To revoke:

1. Rotate the credential at its source (the API provider), so the old value
   stops working anywhere.
2. Remove the reference from the stack and re-apply, or `mc2 down` the stack.
3. Then `mc2 secret rm NAME`.

## The key

`secrets.key` (in the data dir, or at `--secrets-key-path`) is the only way
to decrypt `mc2.db`'s secrets.

- **Back it up with `mc2.db`**; one without the other can't restore secrets.
- The server **refuses to start** if the database holds secrets and the key
  is missing or doesn't decrypt them — it won't silently generate a new key.
- It also refuses a key that's a symlink, shorter than 32 bytes, or
  world-readable (group-readable only warns). Fix permissions with
  `chmod 600`; never replace a key's contents.
- If the key is truly lost: `mc2 server secrets purge --data-dir <dir>`
  lists what would be deleted, `--yes` deletes it, and then you set every
  secret again.
