`mc2 server` serves the REST API that every `mc2` command uses. Anything the
CLI does, you can do with `curl` or your own client.

## Basics

- **Base URL** — the server's `--bind` address (default
  `http://127.0.0.1:7443`), or `https://<public-hostname>` through Traefik.
- **Versioned paths** — operator endpoints live under `/v1/`. `GET /health`
  sits outside it.
- **Instance IDs** — `{id}` in a path is the instance **UUID**. The CLI's
  `stack/service/ordinal` refs are resolved by the CLI; the API returns `404`
  for them. Look up UUIDs with `GET /v1/instances`.
- **JSON bodies** need `Content-Type: application/json`; without it the
  server answers `415`.
- **Field casing varies by endpoint** — some responses use `snake_case`
  (status counters, nodes, instances, volumes, secrets), others `camelCase`
  (resources, exec, logs, SSH, networks). Each endpoint page shows the exact
  fields.

## Authentication

Every `/v1` route needs the API token:

```http
Authorization: Bearer mc2at_...
```

Only `GET /health` is public. A server started with `--no-auth` skips the
check for that run. See [Authentication](/security/authentication) for how
the token is created and rotated.

## Errors and status codes

| Status | When |
| --- | --- |
| `200` | Success with a JSON body. |
| `204` | Success with no body (deletes). |
| `400` | Invalid stack, allocation or capacity refusal, malformed JSON syntax. Body: `{"error": "<message>"}`. |
| `401` | Missing or wrong token. Body: `{"error": "unauthorized", "message": "missing or invalid bearer token"}`. |
| `404` | No such stack, instance, secret, or key. |
| `408` | An ordinary request exceeded `--request-timeout-secs` (default 60). |
| `413` | Request body too large. |
| `415` | JSON body sent without `Content-Type: application/json`. |
| `422` | JSON with the wrong shape (e.g. a missing field). The body is plain text from the JSON decoder. |
| `500` | Internal error. Body: `{"error": "<message with cause>"}`; also logged by the server. |
| `503` | Connection cap reached (`--max-connections`), or `/health` when the loop isn't converging. |

## Limits

- Request bodies are limited to 2 MiB, except `exec` (16 MiB).
- Ordinary requests must finish within `--request-timeout-secs`; `exec` and
  `logs` are exempt (a command or a log stream can run for a long time).
- A client must send its request headers within 30 s.

## Calling it with curl

`curl` doesn't read MC2 contexts; pass the URL and token yourself:

```bash
export MC2_API=http://127.0.0.1:7443
export MC2_API_KEY='mc2at_...'

curl -s -H "Authorization: Bearer $MC2_API_KEY" "$MC2_API/v1/status"

curl -s -H "Authorization: Bearer $MC2_API_KEY" \
  -H 'Content-Type: application/json' \
  -X POST "$MC2_API/v1/stacks:apply" \
  -d '{"yaml":"name: demo\nservices:\n  web:\n    image: alpine:3.20\n"}'
# {"stack":"demo","services":1,"instances":1,"scheduled":1,"pending":0,"ssh":[]}
```
