title: Stacks & instances
description: Apply and delete stacks; list instances; exec, logs, and volumes — request and response shapes.
---

All endpoints here need the bearer token; `{id}` is an instance UUID.

## POST /v1/stacks:apply

Applies a stack. The body is `{"yaml": "<stack YAML>"}`.

```bash
curl -s -H "Authorization: Bearer $MC2_API_KEY" -H 'Content-Type: application/json' \
  -X POST "$MC2_API/v1/stacks:apply" \
  -d '{"yaml":"name: demo\nservices:\n  web:\n    image: alpine:3.20\n"}'
```

```json
{"stack":"demo","services":1,"instances":1,"scheduled":1,"pending":0,"ssh":[]}
```

- **The YAML must include `name:`.** The API has no file name to derive it
  from; without one it returns `400 {"error":"name is required"}`. (Only
  `mc2 up -f` and `mc2 config -f` fill a missing name.)
- **All or nothing.** Validation, capacity, and port checks run before any
  write; a refusal is `400` and changes nothing. Otherwise the stack and every
  instance create/update/delete commit in one transaction.
- **Whole document.** Services missing from the YAML are removed, and a lower
  `scale` removes the highest ordinals. Volumes are never removed by an
  apply.

| Response field | Meaning |
| --- | --- |
| `stack` | The stack name. |
| `services`, `instances` | Counts in the applied document. |
| `scheduled` | Instances placed on the node by this apply. |
| `pending` | Instances that couldn't be placed (e.g. an unmatched `nodeName`). |
| `ssh` | Declared SSH endpoints: `service`, `bind`, `port`, `entrypoint`, `replicas`. |

## DELETE /v1/stacks/{name}

Removes the stack's instances and definition. `?volumes=true` also deletes
its volume directories. Returns `204`, or `404` if the stack doesn't exist —
`?volumes=true` needs the definition to find the volumes, so it must be used
while the stack exists.

```bash
curl -s -H "Authorization: Bearer $MC2_API_KEY" -X DELETE "$MC2_API/v1/stacks/demo?volumes=true"
```

## GET /v1/instances

Every instance on the server:

```json
[
  {
    "id": "6bee1f2c-069f-46c2-927f-6bdbf2ec2469",
    "stack": "api",
    "service": "w",
    "ordinal": 0,
    "node_id": "422229db-1d70-43eb-9084-706331384d83",
    "phase": "Running",
    "runtime_id": "api--w--0",
    "message": "microsandbox sdk (local)",
    "spec_json": "{\"image\":\"alpine:3.20\", ...}",
    "healthy": false,
    "updated_at": "2026-09-28T20:14:13.800705+00:00"
  }
]
```

`phase` is one of `Pending`, `Scheduled`, `Creating`, `Running`, `Stopped`,
`Failed`; `message` carries the reason for a failure and any disk-condition
notes. `spec_json` is the normalized service spec (sizes in bytes, allocated
host ports filled in).

## POST /v1/instances/{id}/exec

Runs a command in the microVM and returns its output.

| Body field | Meaning |
| --- | --- |
| `cmd` | Argv array, required and non-empty. |
| `stdinBase64` | Optional stdin bytes, base64-encoded. |

```bash
curl -s -H "Authorization: Bearer $MC2_API_KEY" -H 'Content-Type: application/json' \
  -X POST "$MC2_API/v1/instances/$ID/exec" \
  -d "{\"cmd\":[\"sh\",\"-c\",\"cat; echo err >&2; exit 3\"],\"stdinBase64\":\"$(printf hello | base64)\"}"
```

```json
{"exitCode":3,"instanceId":"6bee1f2c-...","stderrBase64":"ZXJyCg==","stdoutBase64":"aGVsbG8="}
```

Output is base64 because it needn't be UTF-8. A non-zero exit is still `200`.
The body limit is 16 MiB, so stdin tops out around 12 MiB. The request has no
timeout.

## GET /v1/instances/{id}/logs

| Query | Meaning |
| --- | --- |
| `tail=N` | Only the last `N` entries. |
| `follow=true` | Stream instead of returning once. |

Without `follow`:

```json
{
  "instanceId": "6bee1f2c-...",
  "entries": [
    {"timestamp": "2026-09-28T20:14:13.921+00:00", "source": "stdout", "data": "hello"},
    {"timestamp": "2026-09-28T20:14:13.921+00:00", "source": "stderr", "data": "err\n"}
  ]
}
```

With `follow=true` the response is `text/event-stream`: each event's `data`
is one entry object as above, existing entries first, then new ones as they
arrive, with a keepalive comment every 15 s. The stream has no timeout.

## GET /v1/volumes

Volume directories under the server's volume root (`<data-dir>/volumes`, or
`--volume-dir`):

```json
[
  {
    "name": "mc2-api--data",
    "stack": "api",
    "volume": "data",
    "path": "/home/you/.mc2/volumes/mc2-api--data",
    "limit_mib": 64,
    "used_mib": 0
  }
]
```

`limit_mib` is the declared `size` (`null` once no stack declares the
volume); `used_mib` is measured usage. Non-MC2 directories in the volume root
are ignored. Check this before a `?volumes=true` delete.
