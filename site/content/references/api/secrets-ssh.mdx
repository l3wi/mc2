## Overview

The `/v1/secrets` and `/v1/ssh*` endpoints manage credentials: a server-wide
encrypted secret store and the SSH key registry, endpoints, and per-instance
SSH overrides. All require a bearer token.

## Secrets

`GET /v1/secrets` lists secret names only — **values are never returned**.

| Method | Path | Role |
| ------ | ---- | ---- |
| `GET` | `/v1/secrets` | List secret names (never values) |
| `PUT` | `/v1/secrets/{name}` | Create or replace a secret |
| `DELETE` | `/v1/secrets/{name}` | Delete a secret |

`PUT /v1/secrets/{name}` takes a JSON body `{ "value": "..." }` and returns the
secret metadata; the value is never echoed back.

```bash
curl -s -H "Authorization: Bearer mc2at_..." \
  -X PUT http://127.0.0.1:7443/v1/secrets/SMOKE_TOKEN \
  -d '{"value":"lab-only"}' | jq .

curl -s -H "Authorization: Bearer mc2at_..." http://127.0.0.1:7443/v1/secrets | jq .

curl -s -H "Authorization: Bearer mc2at_..." -X DELETE \
  http://127.0.0.1:7443/v1/secrets/SMOKE_TOKEN
```
`DELETE` returns `204`, or `404` if the secret does not exist.

## SSH keys

The cluster-wide SSH key registry:

| Method | Path | Role |
| ------ | ---- | ---- |
| `GET` | `/v1/ssh/keys` | List authorized keys |
| `PUT` | `/v1/ssh/keys/{name}` | Add or replace a key |
| `GET` | `/v1/ssh/keys/{name}` | Show one key |
| `DELETE` | `/v1/ssh/keys/{name}` | Remove a key |

`PUT /v1/ssh/keys/{name}` takes a JSON body `{ "publicKey": "..." }`.

```bash
curl -s -H "Authorization: Bearer mc2at_..." \
  -X PUT http://127.0.0.1:7443/v1/ssh/keys/laptop \
  -d '{"publicKey":"ssh-ed25519 AAAA... lewi@mbp"}' | jq .

curl -s -H "Authorization: Bearer mc2at_..." http://127.0.0.1:7443/v1/ssh/keys | jq .
```

## SSH endpoints

`GET /v1/ssh/endpoints` lists open SSH endpoints. Each endpoint includes the
instance (`instanceId`, `stack`, `service`, `ordinal`), `nodeId`/`nodeName`,
`bind`, `port`, `phase`, and a `connectHint` like `ssh -p <port> root@<bind>`.

```bash
curl -s -H "Authorization: Bearer mc2at_..." http://127.0.0.1:7443/v1/ssh/endpoints | jq .
```

## Instance SSH

Per-instance SSH state and overrides:

| Method | Path | Role |
| ------ | ---- | ---- |
| `GET` | `/v1/instances/{id}/ssh` | Show SSH state for an instance |
| `PUT` | `/v1/instances/{id}/ssh` | Set the desired SSH override |
| `DELETE` | `/v1/instances/{id}/ssh` | Clear the SSH override |

`PUT` takes a camelCase body: `enabled` (required), optional `bind`, `port`,
`user`, `sftp`, and `authorizedKeys` (key names, required when enabled).
Enabling with no keys, or referencing an unknown key, returns `400`.

```bash
curl -s -H "Authorization: Bearer mc2at_..." \
  -X PUT http://127.0.0.1:7443/v1/instances/<id>/ssh \
  -d '{"enabled":true,"authorizedKeys":["laptop"]}' | jq .

curl -s -H "Authorization: Bearer mc2at_..." -X DELETE \
  http://127.0.0.1:7443/v1/instances/<id>/ssh
```

<Callout type="note" title="Values stay hidden">
  Like the CLI, the secrets API never returns stored values — only names and
  metadata. SSH keys are public key lines and are returned as stored.
</Callout>
