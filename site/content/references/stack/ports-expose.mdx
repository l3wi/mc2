Two independent mechanisms put traffic on a service: `ports[]` forwards
host↔guest traffic (**north-south**) and `expose[]` publishes listeners on the
service network (**east-west**).

```text
     guest VM (web)             MC2 host (loopback)          guest VM (db)
┌────────────────────┐      ┌──────────────────────┐      ┌──────────────┐
│ guest 8000         │◄─────┤ 127.0.0.1:8080+ord   │      │              │
│                    │ports │   (publish)          │      │              │
│                    │      │                      │      │              │
│                    │      │ 127.0.0.1:5432       │◄─────┤ guest 5432   │
│                    │      │   (expose splice)    │expose└──────────────┘
└────────────────────┘      └──────────────────────┘
```

Both planes are **host-loopback only** in v1: a publish and a splice each bind
`127.0.0.1`, never a LAN interface. Reach a published port from outside through
`ingress` (a BYO Traefik on the same host) or the `hostname` sugar below.

## `ports[]` (north-south)

Compose syntax. Short (string) and long (map) forms:

```yaml
ports:
  - "5000:3001"            # published:target
  - "3002"                 # target-only -> auto-allocated host port
  - "mcp.example.com:3003" # hostname sugar -> ingress route + auto host port
  - "127.0.0.1:5001:3004"  # ip:published:target (ip advisory; always loopback)
  - "5002:3005/tcp"        # explicit protocol (also /udp)
  # long form:
  - target: 3006
    published: 5003
    protocol: tcp
    hostname: admin.example.com
```

| Key | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `target` | integer | **yes** | — | Port inside the guest. |
| `published` | integer | no | auto | Host port. **Omit** it for the server to allocate; an explicit `published: 0` in the long form is rejected so the intent is unambiguous. |
| `protocol` | string | no | `tcp` | Use `tcp` or `udp`. Short-form suffixes are lowercased; long-form values are kept as written. Anything other than (case-insensitive) `udp` is treated as TCP — a typo isn't rejected. HTTP ingress backends must be `tcp`. |
| `hostname` | string | no | — | Sugar: also publish this hostname through ingress, routed to `target`. Must be an exact lowercase RFC 1123 hostname — no port, wildcard or trailing dot. |

Long-form keys are closed: any other key (`guest`, `host`, `mode`, a misspelt
`published`, …) is rejected by name rather than silently ignored. In the short
form the protocol is the part after `/` (`"5000:3001/udp"`), and a two-part
entry whose first part is not a number is read as `hostname:target`:

| Short form | Meaning |
| --- | --- |
| `"T"` | guest port `T`, auto host port |
| `"P:T"` | host port `P`, guest port `T` |
| `"H:T"` | route hostname `H` to guest `T` (ingress sugar) + auto host port |
| `"IP:P:T"` | host port `P`, guest port `T` (the IP is advisory; MC2 always binds loopback) |
| `"…/tcp"`, `"…/udp"` | protocol suffix on any of the above |

`"0:T"` is accepted and means the same as omitting `published` (auto).

## Auto host ports and scaling

With `scale > 1`, every replica needs a distinct host port:

- A fixed `published: P` becomes the block `P, P+1, …, P+N-1`; ordinal 0 keeps
  `P`. The block may move between applies — the same apply releases the
  stack's previous block — but it may never land on a taken port.
- A target-only (or hostname-sugar) entry is resolved per replica: each
  `(ordinal, target)` keeps the port it already had, otherwise it takes a free
  port from the **10000–65535** pool.

Allocations are resolved once at apply and **persisted in the stored spec**, so
a port is stable across reconciles, restarts and re-applies. Ingress routes
prefer a healthy `Running` replica (when the service has a health check), then
any `Running` replica, and use *that* replica's own port, so a route follows a
failover. With no replica running, the route is left out of Traefik's file.

### What apply rejects

Every one of these is a `400` returned before any write:

| Rejection | Reason |
| --- | --- |
| `published: 0` in the long form | Ambiguous — omit the key instead. |
| `P + ordinal > 65535` | The fixed block runs past the host port range; lower `published` or `scale`. |
| Auto pool exhausted | No free port in 10000–65535; publish a fixed port or free one. |
| The candidate port is in the taken set | Already an `expose` claim (any stack, including this document's own), another stack's published port, the REST bind (`--bind`), or `:53` (the guest DNS interceptor). |
| The candidate was already handed to another entry in this pass | Two `ports` entries would share a host port. |
| The database refuses the claim | A `(port, protocol)` uniqueness constraint backs every publish and expose, so even two applies racing each other cannot both win the same port. |

Published ports are checked against MC2's own claims only — not against other
programs on the host. If something else already listens on a published port,
apply succeeds and the clash shows up when the microVM starts. (`expose`
ports *are* probed; see below.)

The database claim key is `(port, protocol)`, so TCP and UDP are separate
there — but the apply-time allocator compares port **numbers** only. Don't
reuse a host-port number for both TCP and UDP, within a service or against
another stack's claim; use distinct numbers. `mc2 down` frees the stack's
claims; `mc2 network` lists expose claims and their owners.

## `expose[]` (east-west listeners)

Compose list form or map form:

```yaml
expose: [5432, "6379", "6380/tcp"]   # bare ports (optionally with /protocol)
expose:                              # map form for protocol/name
  - port: 5432
    protocol: tcp
    name: main
```

| Key | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `port` | integer | **yes** | — | Listener port; must be non-zero. |
| `protocol` | string | no | `tcp` | Only `tcp` in v1; anything else is rejected at apply. |
| `name` | string | no | — | Optional listener name (metadata). |

An exposed port is reachable by every service that shares a network with it
(same stack by default, or a named network — see
[Networks & ingress](/references/stack/networks-ingress)) as
`<service>.<network>.svc.mc2:<port>`. Replicas of a service can reach their own
service name. Duplicate `expose.port` values in one service, and the same
exposed port in two services of one stack, are rejected — the splice binds one
host port per exposed guest port.

### What apply rejects

An exposed port is claimed **exclusively server-wide** at `mc2 up`, because the
guest's `gateway:P` maps to host `127.0.0.1:P` with no remap, so the port alone
identifies the splice. Apply returns `400` for:

| Rejection | Reason |
| --- | --- |
| Claimed by another stack | The error names the owning `stack/service` and suggests a free port. Re-applying the *same* stack is fine — it keeps its own claims. |
| Collides with the REST API listener | `--bind` (default `127.0.0.1:7443`). |
| Collides with an SSH listener | Any service's `ssh.port`, in any stack. |
| Collides with a published host port | Any `ports[].published`, including the ones this document resolves (fixed or auto). |
| Port `53` | The guest DNS interceptor owns it. |
| A host process already listens there | MC2 connects first, then test-binds, so a daemon on `*:P` is caught too. |
| Privileged port on Linux | Ports below 1024 need `CAP_NET_BIND_SERVICE`; the error prints the `setcap`/systemd/`ip_unprivileged_port_start` options. |

MC2 then **holds** the `127.0.0.1:<port>` listener from apply until the stack
is removed. While a claim has no running backend it accepts and closes the
connection (and the error/fix is visible in the server log), and MC2 refuses to
create a VM whose allowed port has no listener — it fails closed rather than
leaving an exposed port unrouted.

<Callout type="note" title="Claims survive in the database">
  `host_port_claims` (primary key `(port, protocol)`) is written in the same
  transaction as each apply, for `expose[]` and `ports[].published` alike. Even
  if the application-level checks were bypassed, a second claim on the same
  `(port, protocol)` is refused. `mc2 down` frees the stack's rows.
</Callout>

## Choosing between them

| Need | Use |
| --- | --- |
| Reach a port from the host or from outside (via Traefik) | `ports` (and `ingress`) |
| A peer service should call it over the service network | `expose` |
| Both | Declare both — they are independent mechanisms with independent claims. |
