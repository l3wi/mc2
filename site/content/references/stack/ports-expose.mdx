Two independent mechanisms expose a service: `ports[]` forwards host↔guest
traffic (north-south), while `expose[]` publishes listeners on the shared
networks (east-west).

## `ports[]` (north-south)

Compose syntax. Host ports always bind loopback; expose publicly through
`ingress` or the hostname sugar below (BYO Traefik).

```yaml
ports:
  - "5000:3001"            # published:target
  - "3001"                 # target-only → auto-allocated host port (server picks)
  - "mcp.example.com:3000" # hostname sugar → ingress route for that hostname (TLS, `le`)
  - "127.0.0.1:5000:3001"  # ip:published:target (ip advisory; always loopback)
  - "5000:3001/tcp"        # explicit protocol
```

Long form: `{ target: 3001, published: 5000, protocol: tcp, hostname: "mcp.example.com" }`.
Omit `published` (or use the target-only short form above) → auto host port,
resolved once at apply and persisted (the port is stable across restarts and
re-applies); an explicit `published: 0` in the long form is rejected, so leave
the key out to get the server's allocation.

| Key | Required | Default | Description |
| --- | --- | --- | --- |
| `published` | no | auto | Host port. **Omit** for the server to allocate (`0` is rejected in the long form). |
| `target` | yes | — | Port inside the guest. |
| `protocol` | no | `tcp` | `tcp` or `udp` (`udp` not usable as ingress backend). |
| `hostname` | no | — | Hostname sugar: route this hostname to `target` via ingress (TLS, `le`). Must be an exact lowercase RFC 1123 hostname — no port, wildcard or trailing dot. |

A published port is the north-south gateway; to reach it over the network you
route it through `ingress` (see [Networks & ingress](./networks-ingress)).

## Auto host ports & scaling

When `scale > 1` and a service declares published ports, each replica gets a
distinct host port:

- a fixed `published: P` becomes the block `P, P+1, …, P+N-1` (ordinal 0 keeps
  `P`);
- a target-only (`"3001"` / hostname-sugar) port gets a distinct auto-allocated
  port per replica.

Allocations are stable across re-applies. Moving a fixed `published` base is
fine — the same apply releases the stack's previous block — but `mc2 up` is
refused (`400`) if two entries would need the same host port, if the port is
already an `expose` claim or another stack's publish, or if `published +
ordinal` would exceed `65535`. Ingress routes for a scaled service target a
Running replica (healthy one first when the service declares a healthcheck,
otherwise the lowest ordinal) and use that replica's own port, so a route
fails over when ordinal 0 is down.

<Callout type="note" title="Auto ports persist">
  An auto host port is resolved once at apply and persisted — the same port
  survives restarts and re-applies rather than churning each reconcile.
</Callout>

## `expose[]` (east-west listeners)

Compose list form or map form:

```yaml
expose: [5432, "6379"]        # bare ports
# or map form for protocol/name:
expose:
  - port: 5432
    name: main
```

| Key | Required | Default | Description |
| --- | --- | --- | --- |
| `port` | yes | — | Listener port; non-zero, unique per service. |
| `protocol` | no | `tcp` | Only `tcp` in v1. |
| `name` | no | — | Optional listener name. |

Reachable by every other service that shares a network (same or different
stack) as `<service>.<network>.svc.mc2:<port>` (default-allow, round-robin
across Ready replicas). A service needs no `expose` of its own to reach peers,
and replicas of a service can reach their own service. Same-node only in v1.
See [Networking](/documentation/concepts/networking).

<Callout type="warning" title="Exposed ports are exclusive server-wide, claimed at apply">
  A guest resolves every name to the one gateway IP and msb rewrites
  `gateway:P` to host `127.0.0.1:P` with no remap, so the port alone identifies
  the shared splice. `mc2 up` therefore rejects an `expose` port another stack
  already claims (`400`, naming the owner and suggesting another port), a port
  MC2 already takes — the REST bind, any SSH listener, any published `ports:`
  host port, or `53` — and a loopback port a host process already listens on.
  MC2 then holds the listener from apply until the stack is removed (a client
  sees accept-then-close while no backend is Ready), and refuses to create a
  VM whose allowed port has no listener (fail closed). Ports below 1024 need
  `CAP_NET_BIND_SERVICE` on Linux. `mc2 network` prints the owner of each claim.
  Claims are additionally enforced by a database uniqueness constraint on
  `(port, protocol)` — for `ports[].published` and `expose[]` alike — so even
  two applies racing each other can never both win the same host port.
</Callout>
