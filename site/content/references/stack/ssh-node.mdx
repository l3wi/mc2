## `ssh`

An SSH endpoint served by MC2 on the host — not an `sshd` in the guest, so
the image needs nothing. Short form `ssh: true` (every default below), or a
map:

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | bool | `false` | Serve SSH for this service. `ssh: true` sets it. |
| `bind` | string | `127.0.0.1` | Host address the listener binds. |
| `port` | integer | `0` | Host port; `0` picks a free one (see `mc2 ssh ls`). Must be fixed (non-zero) for an `ingress.tcp` route. |
| `user` | string | `root` | Guest user the session runs as. |
| `sftp` | bool | `true` | Allow SFTP. |
| `authorizedKeys` | list of strings | `[]` | Key names from `mc2 ssh add-key`. Empty means **every** registered key. |

Register keys before applying:

```bash
mc2 ssh add-key developer --file ~/.ssh/id_ed25519.pub
```

```yaml
services:
  web:
    image: alpine:3.20
    ssh:
      enabled: true
      bind: 127.0.0.1
      port: 2222
      authorizedKeys: [developer]
```

- **Fails closed.** `ssh: true` with no registered keys, or an
  `authorizedKeys` entry that doesn't exist, fails that instance during
  reconcile — MC2 never opens an unauthenticated listener. Check `mc2 ps` and
  `mc2 ssh ls`.
- **One listener per replica.** A fixed `port` is used as-is for every
  replica, so with `scale > 1` use `port: 0` (each replica gets its own free
  port) or give SSH to a `scale: 1` service.
- **Overrides.** `mc2 ssh open` / `mc2 ssh close` set a per-instance override
  that wins over this YAML until it's removed with
  `DELETE /v1/instances/{id}/ssh`.
- `mc2 up` prints each service's declared SSH port and TCP entry point.
- Sessions are capped by the server's `--max-ssh-sessions` (64) and
  `--max-ssh-sessions-per-listener` (16); a client has 30 s to finish the
  handshake, and there's no idle timeout.

<Warning title="An empty authorizedKeys admits every key">
  Convenient for a one-person lab; risky once more keys are registered. List
  key names explicitly in shared setups.
</Warning>

## `nodeName` and `nodeSelector`

Placement keys. v1 has exactly one node — the machine running `mc2 server` —
so they only decide whether the instance is placed at all:

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `nodeName` | string | — | Place only on the node with this name (`--node-name`, default the hostname). |
| `nodeSelector` | map | `{}` | Place only on a node whose labels (`mc2 server --label KEY=VALUE`) include all these pairs. |

```yaml
services:
  web:
    image: alpine:3.20
    nodeSelector:
      zone: a        # matches mc2 server --label zone=a
```

If the node doesn't match, the instance stays `Pending` **with no message**;
the apply output shows it as `"pending": 1`. Check `mc2 node ls` for the
node's name and labels. When `nodeName` is set, `nodeSelector` is ignored.
