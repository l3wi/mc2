## Overview

Named contexts let the CLI switch between installs — typically one loopback
context for the local server and one remote context for a production server
over TLS. Contexts are stored in `~/.mc2/config.toml`, written with mode
`0600` so tokens stay private. See
[Identity & contexts](/documentation/concepts/identity-and-contexts) for the
concept.

## File format

`~/.mc2/config.toml` is a TOML document with a top-level `current` key and one
`[contexts.<name>]` table per saved context. TOML requires top-level keys
before the first table, so `current` comes **before** any `[contexts.*]`
header:

```toml
current = "prod"

[contexts.prod]
url = "https://mc2.example.com"
api_key = "mc2at_..."
```

| Field | Meaning |
| ----- | ------- |
| `current` | Top-level key: the active context name, used when no `--context` / `MC2_CONTEXT` is given. Must appear before the first `[contexts.*]` table. |
| `[contexts.<name>]` | A named context: `url` (control plane REST base URL) and optional `api_key` (operator API bearer token) |

The file holds tokens in plaintext and is always written with mode 0600
(via a temporary file and rename, so it's never briefly readable). It's
written by `mc2 context set`, `mc2 context use`, and `mc2 setup client`;
treat it as generated. `context set` doesn't change `current` — run
`mc2 context use` (the wizard does both).

## Resolution precedence

The CLI resolves the **URL** and the **token** separately, each taking the
first value it finds:

| | 1st | 2nd | 3rd | Fallback |
| --- | --- | --- | --- | --- |
| URL | `--api` | `MC2_API` | the context's `url` | `http://127.0.0.1:7443` |
| Token | `--token` | `MC2_API_KEY` | the context's `api_key` | none |

"The context" is `--context` / `MC2_CONTEXT` if given, otherwise `current`.
An explicitly named context must exist, even if `--api` is also given.

Because they resolve separately, `--api` alone still sends the current
context's token — pass `--token` too when pointing at a different server.
`mc2 context use` switches the persisted `current`.

## Managing contexts

| Command | Meaning |
| ------- | ------- |
| `mc2 context set <name> --api <URL> [--token <TOKEN>]` | Create or update a context (upsert) |
| `mc2 context use <name>` | Switch the current context |
| `mc2 context ls` | List contexts (name, URL, mode) and the current one |

```bash
mc2 context set prod --api https://mc2.example.com --token mc2at_...
mc2 context use prod
mc2 status                      # remote: https://mc2.example.com (context: prod)
mc2 context ls
```

<Callout type="warning" title="Remote contexts need TLS">
  A remote (non-loopback) context requires `https://`; plaintext `http://` is
  refused unless you opt in with `--allow-insecure-http` /
  `MC2_ALLOW_INSECURE_HTTP=1`.
</Callout>
