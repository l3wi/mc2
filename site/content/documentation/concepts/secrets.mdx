---
title: Secrets
description: Encrypted at rest, host-gated at runtime — not plaintext env vars.
---

MC2 gives services two distinct ways to get values into a guest's
environment. They look similar in YAML and both end up as environment
variables, but they are different mechanisms with very different security
properties.

## The analogy

`environment:` is like setting a var inline in a compose file — plaintext,
visible to anyone who can read the file. `secrets[].env` is like mounting a
secret that a proxy swaps in at the moment the app talks to an approved
host: the guest never holds the real value.

## Two mechanisms

### `environment:` — direct injection

```yaml
services:
  web:
    image: alpine:3.20
    environment:
      MODE: fast
```

- Plain literals, stored unencrypted in the stack spec and injected at
  create.
- Visible to every command in the guest and to anyone who can read the stack
  file or data dir.
- Keys starting with `MSB_` are rejected (microsandbox-reserved prefix).

**Use for:** non-sensitive configuration — ports, flags, feature toggles.

### `secrets[].env` — host-gated, encrypted secret

```yaml
services:
  web:
    image: alpine:3.20
    secrets:
      - name: SMOKE_TOKEN
        env: API_TOKEN
        allowHosts:
          - api.example.com
```

The stack references a **cluster secret by name**; the value lives once in
the server-wide store (`mc2 secret set`), encrypted at rest.

- MC2 never echoes values back — `mc2 secret ls` and the REST API return
  names/metadata only.
- At reconcile time the value is passed through the microsandbox **secret**
  mechanism, not `Sandbox::env`. The guest sees a placeholder
  (`$MSB_<env>`), and the sandbox's egress proxy enables TLS interception:
  when the guest connects to an `allowHosts` host, the real value is
  attached for that connection. Everywhere else, the placeholder stays.
- `allowHosts` must be non-empty — injection **fails closed**.
- Rotation: `mc2 secret set NAME --value …` then re-apply the stack (the
  sandbox is recreated so the new value is attached).

**Use for:** credentials and tokens that must be encrypted at rest, never
listed, and scoped to specific outbound hosts.

## Scope: server-wide, not per-stack

| | Compose | MC2 |
| --- | --- | --- |
| Declared | top-level `secrets:` in the project file | not in the stack at all |
| Stored | per project, file/env-derived | server-wide store, `mc2 secret set` |
| Scoped to | one project | the whole server |
| Values | plaintext on disk | encrypted at rest |
| Injected | file mount / env | host-gated msb secret (+ TLS interception) |

## Collision precedence

If `environment:` and `secrets[].env` name the **same** env var, the explicit
`environment:` value **wins**. The colliding secret is dropped at desired-set
build (never decrypted), and a warning is logged.

```yaml
environment:
  API_TOKEN: inline-value        # wins — the secret below is dropped
secrets:
  - name: VAULT_TOKEN
    env: API_TOKEN
    allowHosts: [api.example.com]
```

## Key behaviors

- **Encrypted at rest, never listed.** The store is the only copy.
- **The guest never holds the raw value.** It is attached per-connection to
  allowlisted hosts only.
- **Fail closed.** Empty `allowHosts` is an error, not a silent pass-through.
- **Precedence is explicit.** `environment:` overrides on exact-name
  collision.
