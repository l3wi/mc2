A microVM's own disk goes away whenever the microVM is recreated. A
**volume** is a named directory on the server that survives recreates,
restarts, and stack removal. Put anything that must last — databases,
uploads, caches you want to keep — in a volume.

## The analogy

Like a Compose named volume, but backed by a plain directory that MC2 owns on
the server rather than by the Docker daemon. It persists across `mc2 down`
until you delete it explicitly.

## Two kinds of disk

```text
 microVM shop--db--0
 ┌──────────────────────────────────────────┐
 │ root disk (storage_opt.size, def. 4 GiB) │  lost when the microVM is
 │   /usr, /etc, /root, packages, ...       │  recreated
 │                                          │
 │ /var/lib/postgresql/data ◄───────────────┼── volume "data" (size, def.
 └──────────────────────────────────────────┘   10 GiB): a directory on the
                                                 server, kept until deleted
```

- The **root disk** holds the image and anything written outside a volume.
  Size it per service with `storage_opt.size` (default 4 GiB). It survives a
  plain restart of a stopped microVM, but not a recreate (a crash under a
  `restart` policy, or any config change).
- A **volume** is mounted into the microVM at a path you choose and survives
  everything except `mc2 down --volumes`.

## Declaring and mounting

Declare volumes at the top level of the stack, then mount them in services:

```yaml
volumes:
  data:
    kind: dir
    size: 10GiB        # optional; default 10 GiB

services:
  db:
    image: postgres:16
    command: ["postgres"]
    volumes:
      - name: data
        target: /var/lib/postgresql/data
```

- Services can only mount volumes declared at the top level.
- `kind: dir` is the only kind in v1.
- `size` takes Compose byte sizes (`10GiB`, `512m`, or bytes).
- Volume names match `[a-z0-9][a-z0-9._-]*`, can't contain `--` or end with
  `-`, and are at most 63 characters.
- Mount targets must be absolute paths, unique within a service.

## Where the data lives

Each volume is the directory `mc2-<stack>--<volume>` under the server's
**volume root**: `<data-dir>/volumes` by default (`~/.mc2/volumes` with the
default data dir), or wherever `mc2 server --volume-dir` points. The stack
name is part of the directory name, so two stacks can each have a `data`
volume without colliding.

`mc2 volume ls` lists the volume directories on the server with their stack,
declared size, and current usage — check it before a destructive
`mc2 down --volumes`.

## Size caps

`size` is enforced as a write quota. Each time the microVM starts, MC2
measures what the directory already holds and mounts it with the remaining
allowance:

```text
 size: 10GiB
 ├──────── used: 6 GiB ────────┼──── quota for this start: 4 GiB ────┤
                                                  writes past it ──► ENOSPC
```

Inside the guest, `df` shows the cap, and writing past it fails with
`No space left on device`.

- **Grow a volume** by raising `size` and running `mc2 up`. The microVM
  restarts with the new cap; the data is kept.
- **Shrinking** below what the directory already holds is rejected at apply.
- **Replicas share the allowance, not the cap.** If several replicas mount
  the same volume, each gets the remaining allowance when it starts, so
  together they can write more than `size`. Treat a volume as belonging to
  one service replica at a time.
- **Quotas don't protect the host disk.** Declared sizes can add up to more
  than the disk has free. Set `mc2 server --limit-disk-mib` to reserve disk
  at apply time (volume sizes plus root disks × replicas); `mc2 up` then
  refuses a stack that doesn't fit.

## When a disk fills

MC2 checks root disks and volumes as it reconciles (volume usage is
re-measured at most once a minute, so a condition can take up to a minute to
appear). At 90% used it reports a warning; at 99% (or under 64 MiB free) it
reports the disk as full.

- `mc2 ps` shows the condition in its `NOTES` column (for example
  `volume data full`).
- `mc2 exec`, `mc2 ssh open`, and `mc2 logs` print it before running, with the
  exact stack-file change that fixes it.
- `mc2 up` doesn't print it — conditions from before the apply would be
  stale. Check `mc2 ps` after the next pass.

## Lifecycle

| Event | Root disk | Volume |
| --- | --- | --- |
| Command exits, microVM started again | kept | kept |
| Crash or failed health check → recreate | **lost** | kept |
| Config change (`mc2 up`) → recreate | **lost** | kept |
| Volume `size` raised (`mc2 up`) | **lost** | kept |
| `mc2 down <stack>` | **lost** | kept |
| `mc2 down <stack> --volumes` | **lost** | **deleted** |

## Key behaviors

- **Ephemeral by default.** Persisting is an explicit choice: mount a volume.
- **Every volume is capped** by its declared `size`.
- **Local to the server.** There is no replication or migration in v1; back
  up the volume root like any other data directory.
- **`--volumes` is destructive.** It deletes the stack's volume directories.
