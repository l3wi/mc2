A **stack** is the document `mc2 up -f <file>` sends to the server: one YAML
file that describes a set of services and everything they need. It is shaped
like Docker Compose — a top-level `name` and a `services` map, plus optional
top-level `volumes`, `networks`, and `ingress`. Keep it in git next to your
code.

## The analogy

Like `docker-compose.yml`: services, ports, environment, healthchecks,
`depends_on`, volumes, networks. The differences are what make MC2 MC2 —
the parser is *canonical* (unknown keys are rejected, not ignored), and the
file describes a desired state that is reconciled, not a run-once recipe.

## The shape

```yaml
name: shop                        # optional: defaults from the file name
volumes:
  data:
    kind: dir
networks:
  backend:
    mode: mediated

services:
  db:
    image: postgres:16
    command: ["postgres"]         # MC2 doesn't run the image's CMD by default
    environment:
      POSTGRES_PASSWORD: lab-only
    expose: [5432]
    volumes:
      - name: data
        target: /var/lib/postgresql/data
  web:
    image: python:3.12-alpine
    command: ["python", "-m", "http.server", "8000"]
    ports:
      - "8080:8000"

ingress:
  rules:
    - host: shop.local
      paths:
        - path: /
          service: web
          port: 8000
```

A minimal, complete stack can be just:

```yaml
services:
  web:
    image: alpine:3.20
```

`mc2 up` fills a missing `name` from the file name (`shop.yaml` → `shop`, or
the parent directory when the file is called `stack.yaml`), and defaults
`scale`, `cpus`, `mem_limit`, `restart`, `command`, and the network profile.
Run `mc2 config -f <file>` to see the normalized result without applying it.

## What a stack becomes

Each service turns into one **instance** per replica, and each instance is
one microVM. The stack name prefixes everything, so two stacks never collide:

```text
stack "shop"
├── service db            ──► instance shop/db/0    microVM shop--db--0
├── service web (scale 2) ──► instance shop/web/0   microVM shop--web--0
│                         ──► instance shop/web/1   microVM shop--web--1
├── network shop          (implicit; every service joins it)
└── volume data           ──► directory <volume root>/mc2-shop--data
```

You refer to an instance as `stack/service/ordinal` in the CLI
(`mc2 logs shop/web/1`).

## One file is the whole stack

The file you apply is the complete desired state for that stack, not a
patch:

- A service you delete from the file is removed by the next `mc2 up`.
- A lower `scale` removes the highest-numbered replicas.
- An apply that fails validation or planning changes **nothing** — the
  running stack stays as it was.

Other stacks are untouched: an apply only ever changes the stack it names.

## Names

Stack, service and network names are lowercase
`[a-z0-9]([a-z0-9_-]*[a-z0-9])?` — no `--`, no `.`, no uppercase, no spaces —
capped at 40 characters (stack) and 63 (service, network). Volume names allow
`.` as well, cap at 63, and must not contain `--` or end with `-`. An invalid
name is rejected at apply (or `mc2 config`) with a suggested replacement.

Names are also the runtime identity (see the tree above), which is why they
are restricted: `--` is reserved as the separator in `{stack}--{service}--{ordinal}`
and `mc2-{stack}--{volume}`.

## Canonical parsing

MC2 does not silently ignore what it does not understand. Unknown keys —
including the old k8s-style `apiVersion`, `kind`, `metadata`, and fields like
`replicas`, `resources`, `restartPolicy`, `health`, or `env` — are rejected
with `unknown field …`. Apply returns `400` for any validation failure, and
`mc2 config -f <file>` validates and prints the normalized document without
applying anything.

## Validation

Apply returns `400` for: empty services; a missing `name` or one violating the
[name grammar](#names); service, network or volume names that violate theirs;
undeclared volume mounts; non-`dir` volume kinds; relative or duplicate mount
targets; `scale: 0`; unknown `restart` values; non-mediated networks; unknown
or duplicated `network.profiles` values; zero or duplicate `expose` ports;
ingress with invalid hosts, paths or Traefik identifiers, duplicate routers, a
non-tcp backend, or TCP routes without a fixed SSH port; and `depends_on`
references to unknown services, unknown conditions, or cycles.

## Key behaviors

- **Defaults are applied, not required.** Partial files work; the server
  normalizes them and stores the result.
- **`name` is the stack's identity.** `mc2 down <name>` targets it; it also
  names the stack's default network and prefixes its volumes.
- **The file is the request, not the record.** What was accepted and what is
  running lives in the server's database; re-applying converges.
