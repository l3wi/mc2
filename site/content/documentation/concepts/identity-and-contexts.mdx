title: Identity & contexts
description: The API token, local vs remote connections, and how the CLI decides which server to talk to.

The `mc2` CLI is a REST client. Every command needs two things: **which
server** (its URL) and **proof you may use it** (the API token). A
**context** saves both under a name, so the same commands work against the
server on your laptop or one across the internet.

## The analogy

Like `kubectl` contexts or `docker context`: named connection settings plus a
`current` pointer. The difference is that the MC2 CLI refuses to send a token
to a remote server over plain HTTP unless you explicitly allow it.

## The API token

```text
 first start ──► server creates a token ──► shown once: terminal, or
                         │                  <data-dir>/bootstrap-token
                         ▼
                 mc2.db stores only its hash

 each request ──► Authorization: Bearer mc2at_… ──► hash matches? ──► 200
                                                                └──► 401
```

- The server keeps only a hash of the token, so it can't show it to you
  again. Store it in your password manager or a context.
- **Every `/v1` route needs the token**, whether you connect from loopback or
  remotely. Only `/health` is public.
- **Lost it?** On the server machine, run `mc2 server token rotate` (add
  `--data-dir` if you use a non-default one). It prints a new token and the
  old one stops working immediately — the server doesn't need a restart.
- **Lab shortcut:** `mc2 server --no-auth` skips the check for that run only.
  It is refused on a non-loopback `--bind` unless you add
  `--allow-unauthenticated-remote`, and never allowed with
  `--public-hostname`.

## Choosing the server

The CLI resolves the URL and the token **separately**, each taking the first
value it finds:

```text
 URL:    --api   ▸ MC2_API     ▸ context url     ▸ http://127.0.0.1:7443
 token:  --token ▸ MC2_API_KEY ▸ context api_key ▸ (none)

 context = --context ▸ MC2_CONTEXT ▸ current in ~/.mc2/config.toml
```

Because they resolve separately, `--api` alone still sends the current
context's token. Pass `--token` too when pointing at a different server.

```bash
# One-off
mc2 --api https://mc2.example.com --token 'mc2at_…' status

# Saved: create, switch, use
mc2 context set prod --api https://mc2.example.com --token 'mc2at_…'
mc2 context use prod
mc2 status
```

Contexts live in `~/.mc2/config.toml` on the **client** machine (mode 0600,
token included). `mc2 context ls` lists them with their mode and marks the
current one.

## Local vs remote

The URL's host decides the mode:

| Mode | Host | Transport |
| --- | --- | --- |
| **Local** | `127.0.0.0/8`, `::1`, `localhost` | `http://` is fine — traffic never leaves the machine |
| **Remote** | anything else | `https://` required; the CLI refuses `http://` unless you pass `--allow-insecure-http` or set `MC2_ALLOW_INSECURE_HTTP=1` |

The token is required in both modes (unless the server runs `--no-auth`).
The HTTPS rule is enforced by the CLI; the server itself speaks plain HTTP on
its bind address and expects TLS to be terminated in front of it — normally
by Traefik via `--public-hostname`.

## Remote management

`mc2 setup` is a wizard that prints commands; it never starts the server or
Traefik itself.

1. **On the server:** `mc2 setup server`. Choose the bind, data dir, public
   hostname, and Traefik settings, then start the `mc2 server …` command it
   prints. Save the token it shows (or read `<data-dir>/bootstrap-token`).
2. **On your machine:** `mc2 setup client`. Enter a context name, the URL
   (e.g. `https://mc2.example.com`), and the token. It saves the context,
   makes it current, and can test the connection.

The hand-typed equivalent is `mc2 server --public-hostname mc2.example.com …`
on the server and `mc2 context set prod --api https://mc2.example.com --token
'mc2at_…'` on your machine. See
[Manage a remote server](/documentation/guides/manage-a-remote-server).

## Key behaviors

- **The CLI keeps no hidden state.** Everything it knows is in flags, the
  environment, or the contexts file.
- **One token, stored as a hash.** Rotate it rather than trying to recover
  it.
- **Remote means HTTPS.** Opting out is explicit and per-invocation or
  per-environment.
