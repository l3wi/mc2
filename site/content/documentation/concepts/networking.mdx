title: Networking
description: Three planes — host ports, service networks, and ingress — that compose independently.

MC2 has three network planes. They solve different problems and compose
together:

1. **Host ports** (`ports`) — *outside-in* access to a single instance.
2. **Service networks** (`expose` + `networks`) — *inside-in* communication
   between services.
3. **Ingress** (`ingress:` + `ports`) — *hostname* routing through a BYO
   Traefik proxy.

## The analogy

Compose has `ports` and `expose`; Kubernetes has NodePort/Ingress and the pod
network. MC2 keeps the Compose vocabulary but the model is deliberate: host
ports are loopback-only by default, services on a shared network reach each
other by default (Docker-style), and anything you want reachable by name or
from outside goes through ingress.

## 1. Host ports (north–south)

`ports` maps a host port to a guest port. Host ports **always bind loopback**
— the public path is ingress, not an open host bind.

```yaml
services:
  web:
    image: alpine:3.20
    ports:
      - "8080:8000"       # fixed published:target
      - "8001"            # target-only → auto host port (stable)
      - "mcp.example.com:3000"  # hostname sugar → ingress route (TLS)
```

With `scale > 1`, each replica gets a distinct host port (`8080, 8081,
8082`); target-only ports get a distinct auto port per replica.

## 2. Service networks (east–west)

A service declares `expose` (internal listeners). Every other service that
shares a **network** reaches it by default via the node loop's L4 splice,
with `<service>.<network>.svc.mc2` DNS. A service needs no `expose` of its own
to be a client — it still gets an egress edge to each peer port on its
networks — and replicas of one service can reach their own service's name and
port (the splice round-robins across them).

```yaml
services:
  echo:
    image: alpine:3.20
    expose: [8080]
  client:
    image: alpine:3.20
```

```bash
mc2 exec smoke/client/0 wget -qO- http://echo.smoke.svc.mc2:8080/
```

- **Default-allow.** No allow edges to declare — sharing a network is enough.
- **Networks are server-wide.** Named networks need no top-level declaration;
  stacks can join the same one, so services in *different* stacks can talk.
- **`mc2 network`** lists every network and its members; `mc2 network <name>`
  drills in; `mc2 network <stack>/<service>/<ordinal>` shows one instance's
  observed exposes/edges; it also prints the owner of every claimed port.
- **Exposed ports are exclusive server-wide, claimed at apply.** A guest
  resolves every name to the one gateway IP and msb rewrites `gateway:P` to
  host `127.0.0.1:P` with no remap, so a splice can only tell services apart by
  port. `mc2 up` therefore rejects an `expose` port another stack already
  claims (400, naming the owner), a port MC2 already takes (the REST bind, any
  SSH listener, any published `ports:` host port, or 53), and a port a host
  process is already listening on — unlike Docker, same-port isolation across
  networks isn't possible in v1. Pick another port and update the client's
  connection string.
- **The listener is held for the claim's lifetime**, from apply until the stack
  is removed — even while the service has no Running backend. A client then sees
  *accept-then-close* instead of *connection refused*, and no host process can
  take the port while the claim lives.
- **Privileged ports on Linux.** A non-root server can't bind `expose: 80/443`
  (or any port below `net.ipv4.ip_unprivileged_port_start`), so `mc2 up` rejects
  them with the exact fix: grant `CAP_NET_BIND_SERVICE` (`setcap` or systemd
  `AmbientCapabilities`), lower the unprivileged threshold, or choose a port
  above 1023.
- **Fail closed.** If the listener somehow can't bind by the time an instance
  would be created, that instance is reported `Failed` (naming the port and the
  cause) and its microVM is **not** created: the egress rule is create-time, so
  a guest whose `Host:tcp:P` rule could reach a foreign process must never start.
- **Minimal churn.** A sandbox is recreated only when the *set* of allowed
  ports on its networks changes — not when a neighbour is renamed, restarted, or
  moved. Adding a new `expose` port recreates the services that can reach it,
  because their egress rule is create-time.

## 3. Ingress (north–south HTTP/TCP)

`ingress:` plus `ports:` produces a Traefik file-provider catalog that MC2
writes to `--ingress-config-dir`. You run your own Traefik pointing its file
provider there.

```yaml
ingress:
  tls:
    enabled: true
    certResolver: le
  rules:
    - host: shop.local
      paths:
        - path: /
          pathType: Prefix
          service: web
          port: 8000
  tcp:
    - name: web-ssh
      entryPoint: ssh
      service: web       # requires ssh.enabled with a fixed port
```

The control plane can publish *itself* through the same catalog with
`--public-hostname`, so `https://mc2.example.com` terminates TLS at your
Traefik and reaches the REST API.

## Network profiles

Each service also picks an egress profile via `network.profiles`: `public`
(default), `private`, `host`, or `none`. The set is closed — any other value
(including the former `local`/`any` spellings) is rejected at apply, never
silently treated as `public`. `none` must be the only entry and disables the
guest network entirely; duplicates are rejected. `host` gives the guest the
whole host loopback — the control API and every published port — so `mc2 up`
refuses it unless the server was started with `--allow-host-profile` (env
`MC2_ALLOW_HOST_PROFILE`); see
[Run the server](/documentation/operations/run-the-server). An empty list keeps
the `public` default. Network-reachable ports are always allowed via narrow
rules regardless of profile.

## Key behaviors

- **Three planes, three jobs.** Ports for one instance, networks for
  service-to-service, ingress for hostnames and TLS.
- **Loopback-only host binds.** Nothing public is bound by accident.
- **Server-wide names.** Networks and their DNS live at the server level, not
  per stack.
- **Same-node in v1.** L4 splices and DNS are node-local.
