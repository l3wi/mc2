MC2 connects things in three separate ways. Each solves one problem, and a
service can use any combination:

| Plane | Stack keys | Who connects | To what |
| --- | --- | --- | --- |
| **Host ports** | `ports` | you, on the server machine | one instance |
| **Service networks** | `expose`, `networks` | other services (guests) | a service, by name |
| **Ingress** | `ingress`, hostname `ports` | the internet, via your Traefik | a service, by hostname |

```text
 You on the host ──► 127.0.0.1:published ─────────────────► instance:target
 Another guest   ──► <service>:port ──► MC2 splice ───────► a ready replica
 Internet        ──► your Traefik ──► 127.0.0.1:published ─► instance:target
```

## The analogy

Compose has `ports` and `expose`; Kubernetes has NodePort, Ingress, and the
pod network. MC2 keeps the Compose vocabulary with stricter defaults:
published host ports bind loopback only, services on a shared network reach
each other's exposed ports by default, and public traffic arrives through a
Traefik proxy you run.

## 1. Host ports

`ports` maps a host port to a guest port. Host ports **always bind
`127.0.0.1`** — nothing is published on a public interface by accident. The
public path is ingress.

```yaml
services:
  web:
    image: alpine:3.20
    ports:
      - "8080:8000"              # host 8080 → guest 8000
      - "8001"                   # guest 8001 → an automatic host port
      - "mcp.example.com:3000"   # hostname → an ingress route to guest 3000
```

With `scale: 3`, `8080:8000` becomes host ports 8080, 8081, and 8082, one per
replica. Automatic ports start at 10000 and stay the same across re-applies.
The assigned host ports are in each instance's spec: `mc2 ps -o json` (the
`ports` list inside `spec_json`).

## 2. Service networks

A service lists the ports it serves in `expose`. Any service that shares a
**network** with it can connect to those ports by name.

- Every stack has an implicit network named after the stack, and every service
  in the stack joins it. Add `networks: [name]` to also join a named network,
  which can be shared across stacks.
- Inside the guest, a peer resolves as just `<service>`, or by its full
  name: `<service>.<stack>.svc.mc2` for a service in the same stack, and
  `<service>.<network>.svc.mc2` (the shared named network) for a service in
  another stack.
- A client needs no `expose` of its own, and replicas of a service can reach
  their own service's name.

```yaml
name: smoke
services:
  echo:
    image: python:3.12-alpine
    command: ["/bin/sh", "-c", "mkdir -p /tmp/www && echo hello > /tmp/www/index.html && cd /tmp/www && exec python -m http.server 18100"]
    expose: [18100]
  client:
    image: alpine:3.20
```

Save it as `smoke.yaml`, run `mc2 up -f smoke.yaml`, wait for `mc2 ps` to
show both instances `Running`, then:

```bash
mc2 exec smoke/client/0 wget -qO- http://echo.smoke.svc.mc2:18100/
# hello
```

### How a connection travels

Inside a guest, every service name resolves to the same gateway address, so
the **port** is what identifies the service. The connection leaves the
microVM, reaches a listener MC2 holds on the host (a **splice**), and is
forwarded to one of the service's ready replicas, round-robin:

```text
 client microVM             host                          echo microVMs
 ──────────────             ────                          ─────────────
 echo:8080 ──► gateway ──► 127.0.0.1:8080 (MC2 splice) ──► replica :8080
                                   │
                                   └──► round-robin over ready replicas
```

This design has consequences you'll notice:

- **Exposed ports are exclusive server-wide.** Only one stack can expose a
  given port, because the port *is* the service's address. `mc2 up` rejects
  an `expose` port that another stack holds (naming the owner), a port MC2
  itself uses (the REST port, SSH ports, any published host port, `53`), or
  a port a host process is already listening on. Pick another port and
  update the client's connection string.
- **The listener is held for the stack's lifetime.** From apply until the
  stack is removed, MC2 keeps `127.0.0.1:<port>` bound — even when no replica
  is running. Clients then get *accept-then-close* rather than *connection
  refused*, and no other process can take the port.
- **Fail closed.** If that listener can't be bound when an instance is about
  to be created, the instance is reported `Failed` (naming the port) and its
  microVM is not created.
- **Privileged ports on Linux.** A non-root server can't bind ports below
  1024, so `expose: [80]` is rejected with the fix: grant the binary
  `CAP_NET_BIND_SERVICE`, lower `net.ipv4.ip_unprivileged_port_start`, or use
  a port above 1023.
- **Few recreates.** A client's allowed ports are fixed when its microVM is
  created. It is recreated only when the set of ports it can reach changes
  (for example, a peer exposes a new port) — not when a neighbour restarts or
  changes its backend.

`mc2 network` lists every network, its members, and the owner of every
claimed port; `mc2 network <name>` or `mc2 network <stack>/<service>/<ordinal>`
drills in.

## 3. Ingress

Ingress gives a service a public hostname. MC2 doesn't run a proxy: it writes
a [Traefik file-provider](https://doc.traefik.io/traefik/providers/file/)
catalog to `--ingress-config-dir`, and your Traefik routes traffic to the
instance's loopback host port.

```yaml
ingress:
  tls:
    enabled: true
    certResolver: le
  rules:
    - host: shop.example.com
      paths:
        - path: /
          pathType: Prefix
          service: web
          port: 8000
```

Routes follow a `Running` replica (a healthy one first) and are rewritten
only when they change. TCP routes (`ingress.tcp`) exist for SSH; see
[Open SSH](/documentation/guides/open-ssh). The control plane can publish
itself through the same catalog with `--public-hostname`.

## Egress profiles

`network.profiles` controls what a guest may reach **outbound**, besides its
service-network peers:

| Profile | Guest may reach |
| --- | --- |
| `public` (default) | public internet addresses |
| `private` | private (LAN) address ranges |
| `host` | the host's own loopback — every published port *and* the REST API |
| `none` | nothing: networking is disabled, including service networks |

Profiles combine (`[public, private]`); `none` must be the only entry. Any
other value is rejected. Because `host` exposes the control plane to the
guest, `mc2 up` refuses it unless the server runs with `--allow-host-profile`.

With networking enabled, MC2 adds narrow allow rules for exactly the peer
ports a service can reach, so `public` or `private` alone never cut a service
off from its networks.

## Key behaviors

- **Three planes, three jobs.** Ports for you, networks for services, ingress
  for the internet.
- **Loopback-only host binds.** Nothing public is bound unless your Traefik
  binds it.
- **Default-allow within a network.** Sharing a network is permission; use
  separate networks to separate services.
- **One port, one owner.** Exposed ports are unique across the whole server.
- **Single machine in v1.** Splices and DNS are local to the server.
