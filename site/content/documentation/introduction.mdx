MicroCommandControl (**MC2**) runs Docker-Compose-style stacks where every
replica is its own microVM. You describe services in a YAML file; MC2 boots
each replica on [microsandbox](https://microsandbox.dev) and keeps them
matching that file — replicas, restarts, health checks, startup ordering,
encrypted secrets, service-to-service networking, and Traefik ingress.

It's for developers and operators who know Compose and want real VM
isolation on a machine they control, without adopting Kubernetes or wiring
up a hypervisor by hand.

## The mental model

Three ideas carry the whole system:

1. **You declare a stack.** One YAML file describes the services, ports,
   volumes, networks, secrets, and ingress you want.
2. **MC2 converges it.** One server process stores what you applied and runs
   a *reconcile loop* that keeps real microVMs matching it — creating,
   health-checking, restarting, and removing them.
3. **Each replica is isolated.** Every replica is a microVM with its own
   kernel. It can't see another replica's processes or disk, and it reaches
   other services only where the stack connects them.

```text
   you declare          MC2 converges            on your machine
 ┌─────────────┐      ┌─────────────────┐      ┌─────────────────┐
 │ stack.yaml  │─up──►│ mc2 server      │─────►│ microVM         │
 │ (desired)   │      │ SQLite + loop   │      │ microVM   ...   │
 └─────────────┘      └─────────────────┘      └─────────────────┘
                       keeps them matching       one per replica
```

There's nothing else to install or run: `mc2 server` is the whole control
plane, and the `mc2` CLI is a thin client that talks to it over REST.

## Where it fits

| | MC2 | Docker Compose | Kubernetes | Bare microVMs |
| --- | --- | --- | --- | --- |
| Isolation | microVM per replica | container (shared kernel) | container | microVM |
| Model | desired state, kept converged | run once | controllers | you drive each VM |
| Scope | one machine, one process | one host | a cluster | no orchestration |
| Interface | Compose-style YAML + `mc2` | Compose YAML | manifests + `kubectl` | SDK / CLI |

## What you get

- **Compose-shaped stacks.** `services`, `scale`, `ports`, `expose`,
  `environment`, `healthcheck`, `restart`, `depends_on`, `volumes`,
  `networks`, and `ingress`, in a file you commit. Unknown keys are rejected,
  not silently ignored.
- **Kept converged.** `mc2 up` applies the whole file in one step — or
  rejects it and changes nothing. Crashed replicas are restarted per their
  policy; `mc2 down <stack>` tears everything down.
- **Everything local.** microVMs run on your machine or a server you control,
  with no account or hosted service. `mc2 exec` and `mc2 logs --follow` are
  built in.
- **Secrets the guest never holds.** Values are encrypted in the server's
  store and never listed back. The guest sees a placeholder; the real value
  is added only to TLS connections to hosts you allow.
- **A service network.** `expose` a port and other services on the same
  network reach it by name (`<service>`, or `<service>.<stack>.svc.mc2`).
  `mc2 network` shows who can reach what.
- **Ingress through Traefik.** Give a service a hostname and MC2 writes the
  Traefik routes, including for its own API.

## What people build

- **A swarm of agents.** `scale: 20` puts each agent in its own microVM;
  `restart` keeps them alive, and `mc2 exec` gets you into any of them.
- **Compose projects, on microVMs.** The same `services`, `ports`,
  `depends_on`, and `environment` shape, with each service booted as a VM
  from its image — no image builds.
- **Remote coding agents over SSH.** `ssh: true` plus a key from
  `mc2 ssh add-key` gives each dev VM an SSH endpoint. It listens on the
  server's loopback; reach it through a tunnel or a Traefik TCP route.
- **A throwaway test grid.** Bring up N identical VMs, run your suite, then
  `mc2 down <stack> --volumes` — or keep a cache volume for next time.
- **A fleet of headless browsers.** Each scraper in its own disposable
  microVM, with an egress profile (`public`, `private`, or `none`) per
  service.

## A first look

A stack file can be this small:

```yaml
# web.yaml
services:
  web:
    image: python:3.12-alpine
    command: ["python", "-m", "http.server", "8000"]
    ports: ["8080:8000"]
```

```bash
mc2 up -f web.yaml     # stack name "web" comes from the file name
mc2 ps                 # web/web/0 → Running
curl http://127.0.0.1:8080/
```

Unlike Compose, MC2 doesn't run the image's default command: without
`command`, the microVM runs `sleep infinity` so you can `mc2 exec` into it.
Set `command` for anything that should serve.

## v1 scope

MC2 is pre-release (0.x) and deliberately small:

- **One machine, one process.** No clustering or distributed store.
- **Service networking is local** to that machine.
- **Directory volumes only** (`kind: dir`); no disk images or snapshots.
- **Traefik is the only ingress proxy** MC2 writes configuration for.
