`mc2 server` **is** the orchestrator — one process that owns the SQLite store,
the REST API, the scheduler, the reconcile loop, the network splices, the SSH
listeners, and the Traefik catalog writer, and runs the microVMs through the
embedded microsandbox SDK. There is no agent and no separate daemon. This page
is the operator reference for running it: flags, bootstrap, data layout,
supervision, and limits. For the mental model see
[Architecture](/documentation/concepts/architecture); for your very first run
see [Quickstart](/documentation/quickstart).

## Start it

```bash
mc2 setup      # first run: choose options, print the exact `mc2 server` command
mc2 server     # defaults: bind 127.0.0.1:7443, data dir ~/.mc2, auth on
```

The server registers the local node **before** the REST listener accepts, so an
apply never sees an empty node list. `--init-only` bootstraps the data dir and
token and exits without listening.

To run under a service manager, keep the process in the foreground and let the
manager own restarts:

```ini
# /etc/systemd/system/mc2.service
[Unit]
Description=MC2 orchestrator
After=network-online.target

[Service]
# A dedicated user that owns /srv/mc2 and may open /dev/kvm.
User=mc2
Group=mc2
SupplementaryGroups=kvm
ExecStart=/usr/local/bin/mc2 server
Environment=MC2_DATA_DIR=/srv/mc2
Restart=on-failure
RestartSec=2
# Only if stacks `expose:` a privileged port (< 1024) on Linux:
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target
```

Without a terminal, the first start writes the API token to
`/srv/mc2/bootstrap-token`; read it, then delete the file. With
`MC2_DATA_DIR=/srv/mc2`, volumes live in `/srv/mc2/volumes` too.

On macOS, a `launchd` LaunchDaemon with `KeepAlive` does the same job: run
`mc2 server` in the foreground and let the daemon restart it on a non-zero
exit. Give the service user ownership of the data dir so it can create
`mc2.db`, `secrets.key`, and the volume directories.

## Server flags

A flag overrides its environment variable where one is listed. The last
four rows are the CLI's global connection flags; `mc2 server` accepts them
but doesn't use them — even `mc2 server token rotate` and
`mc2 server secrets purge` work directly on the local `--data-dir`.

| Flag | Env | Default | Description |
| --- | --- | --- | --- |
| `--bind` | `MC2_BIND` | `127.0.0.1:7443` | Address the operator REST API binds |
| `--data-dir` | `MC2_DATA_DIR` | `~/.mc2` | State directory: SQLite, tokens, secrets key, default volume root |
| `--secrets-key-path` | `MC2_SECRETS_KEY_PATH` | `<data-dir>/secrets.key` | 32-byte secret-store encryption key |
| `--volume-dir` | `MC2_VOLUME_DIR` | `<data-dir>/volumes` | Root of MC2-owned named-volume directories |
| `--node-name` | `MC2_NODE_NAME` | hostname | Node display name (identity is persisted) |
| `--label KEY=VALUE` | — | — | Node label (repeatable) |
| `--reconcile-interval-secs` | `MC2_RECONCILE_INTERVAL_SECS` | `10` | Reconcile loop interval |
| `--ingress-config-dir` | `MC2_INGRESS_CONFIG_DIR` | — | Directory for the Traefik file-provider catalog |
| `--public-hostname` | `MC2_PUBLIC_HOSTNAME` | — | Publish this control plane through the ingress catalog |
| `--public-tls-cert-resolver` | `MC2_PUBLIC_TLS_CERT_RESOLVER` | `le` | Traefik cert resolver for that route |
| `--init-only` | — | `false` | Bootstrap the data dir and token, then exit (no listen) |
| `--no-auth` | `MC2_NO_AUTH` | `false` | Skip API auth **for this run** (lab only; see below) |
| `--allow-unauthenticated-remote` | `MC2_ALLOW_UNAUTHENTICATED_REMOTE` | `false` | Confirm `--no-auth` on a non-loopback bind |
| `--allow-host-profile` | `MC2_ALLOW_HOST_PROFILE` | `false` | Permit `network.profiles: [host]` (whole host loopback) |
| `--max-connections` | `MC2_MAX_CONNECTIONS` | `256` | Concurrent REST connections; beyond it the listener answers `503` (minimum 1) |
| `--request-timeout-secs` | `MC2_REQUEST_TIMEOUT_SECS` | `60` | Whole-request deadline for ordinary routes (`exec`/`logs` exempt; `0` disables) |
| `--max-ssh-sessions` | `MC2_MAX_SSH_SESSIONS` | `64` | Concurrent SSH sessions across every instance listener (minimum 1) |
| `--max-ssh-sessions-per-listener` | `MC2_MAX_SSH_SESSIONS_PER_LISTENER` | `16` | Concurrent SSH sessions for one instance listener (minimum 1) |
| `--limit-cpus` | `MC2_LIMIT_CPUS` | `0` (unlimited) | Max reserved CPUs across the cluster |
| `--limit-memory-mib` | `MC2_LIMIT_MEMORY_MIB` | `0` (unlimited) | Max reserved memory (MiB) across the cluster |
| `--limit-disk-mib` | `MC2_LIMIT_DISK_MIB` | `0` (unlimited) | Max reserved disk (MiB): volume sizes + root disks × replicas |
| `--api` | `MC2_API` | — | REST base URL (overrides `MC2_API` and the current context) |
| `--token` | `MC2_API_KEY` | — | Operator bearer token |
| `--context` | `MC2_CONTEXT` | — | Named context from `~/.mc2/config.toml` |
| `--allow-insecure-http` | — | `false` | Allow plaintext `http://` to a remote control plane |
| `-h`, `--help` | — | — | Print help |

Two flag combinations are refused at startup: **`--no-auth` with anything but a
loopback `--bind`** needs `--allow-unauthenticated-remote` (which logs a
warning on every start), and **`--no-auth` together with `--public-hostname`**
is always refused. `--public-hostname` must be an exact lowercase RFC 1123
hostname (no port, wildcard, or trailing dot) and `--public-tls-cert-resolver`
must match `[A-Za-z0-9_-]+`.

## First run & bootstrap

A token is **always** created on first init — `--no-auth` only skips the check
for that one process. The database stores only the token's hash; the
plaintext is handed to you once:

1. Start `mc2 server` (or `mc2 setup`).
2. Capture the token, shown **once**: on a TTY it is printed to stderr; with no
   TTY it is written to `<data-dir>/bootstrap-token` (mode `0600`) and only the
   path is printed — token values never reach journald or a container log.
3. Read it, save it, delete the file. On the client, `mc2 setup client` stores
   it, or `export MC2_API_KEY='mc2at_…'` for a one-off.

Lost it? Mint a new one in place — the old token stops working immediately:

```bash
mc2 server token rotate --data-dir ~/.mc2    # prints the new token once
mc2 context set <name> --api <url> --token <new>
```

`token rotate` writes SQLite directly, so it works whether or not the server is
running (tokens are checked per request).

## The data dir

```text
<data-dir>/            # --data-dir, default ~/.mc2
├─ mc2.db              # SQLite state: stacks, instances, claims, token hash
├─ secrets.key         # 32-byte key, 0600 — back up together with mc2.db
├─ bootstrap-token     # one-time first token (0600); delete once saved
└─ volumes/            # default volume root; one directory per volume
```

**`mc2.db` and `secrets.key` are a pair.** Stored secret values are encrypted
with `secrets.key`, so a database restored without its matching key cannot be
read: the server **refuses to start** rather than silently re-key.

To back up:

1. Stop the server, then copy `mc2.db` and `secrets.key` together (and the
   key at `--secrets-key-path` if you moved it).
2. Volumes need more care: stopping MC2 does **not** stop the microVMs, and
   they keep writing to their volumes. Quiesce the applications (or
   `mc2 down` the stacks) before copying the volume root, or use your
   applications' own backup tools. Include `--volume-dir` if it's outside
   the data dir.

If the key is truly gone, the recovery path deletes the undecryptable rows and
you re-set the values afterwards:

```bash
mc2 server secrets purge --data-dir ~/.mc2          # list what would be deleted
mc2 server secrets purge --data-dir ~/.mc2 --yes    # actually delete
mc2 secret set <name>                               # re-supply the values
```

The server also refuses to start on a `secrets.key` that is a symlink, shorter
than 32 bytes, or world-readable (a group-readable key only warns).

## Supervision & health

The reconcile loop and the REST listener are **critical**: if either ends or
panics, the server logs the cause and exits **non-zero**, so systemd/launchd
restarts it instead of leaving a half-dead process. The metrics exporter is
non-critical and is restarted with backoff.

```text
        a critical task ends              SIGINT / SIGTERM
                │                                │
                ▼                                ▼
   log the cause, exit non-zero      cancel loop, splices, SSH, REST
   (service manager restarts)                │
                                             ▼
                                 drain in-flight REST ≤ 5 s,
                                 then abort whatever is left
                                             │
                                             ▼
                                 whole shutdown ≤ 10 s — even with
                                 a `logs --follow` stream open
                                             │
                                             ▼
                                 running VMs are left alone and are
                                 adopted on the next start
```

`GET /health` is the unauthenticated readiness probe. It answers `200`
(`{"service":"mc2-server","status":"ok"}`) while the reconcile loop is alive
and its last **successful** pass is no older than
`3 × --reconcile-interval-secs + 30 s` (measured from startup until the first
pass). After that, or once the loop has died, it returns `503` with a
`reason`, so a load balancer or service manager can act on an orchestrator
that is up but no longer converging. Use it for readiness; the process exits
on its own when it can't continue.

A restart doesn't stop running microVMs, but it isn't invisible either: while
the server is down, the REST API, service-network splices, and SSH endpoints
are unavailable, and on the next start MC2 recreates any microVM whose
configuration no longer matches (losing files outside volumes).

## Adoption across restarts

Every sandbox MC2 creates carries an install label (`mc2.install`, generated on
first boot). On startup the node lists the sandboxes with that label and:

- **adopts** them;
- removes any whose applied config no longer matches the stack spec (including
  ones created before a config hash was recorded), recreating them;
- deletes labelled sandboxes no stack wants any more.

Sandboxes **without** the label are never touched, and a sandbox is forgotten
only after its removal actually succeeds — a transient failure is retried every
pass. The node's identity is persisted, so `--node-name` (or a hostname change)
only renames it; placements and their VMs stay put.

## Listener limits

Both listeners are admission-controlled, because behind Traefik every client
looks like `127.0.0.1` — so these caps are **global**, with no per-IP limits.

- **REST.** `--max-connections` caps concurrent connections; the connection
  past the cap is answered `503` and closed rather than queued. A client that
  does not finish sending request headers within **30 s** is disconnected, and
  ordinary routes have a whole-request deadline of `--request-timeout-secs`
  (default `60` s). `POST /v1/instances/{id}/exec` (a command can run for
  minutes) and `GET /v1/instances/{id}/logs` (an infinite SSE stream, with a
  keepalive every 15 s) are **exempt**. The body limit is axum's 2 MiB default
  everywhere except `exec`, which accepts **16 MiB** of request bytes
  (≈ 12 MiB of raw stdin after base64).
- **SSH.** `--max-ssh-sessions` caps sessions per server and
  `--max-ssh-sessions-per-listener` per instance; connections beyond either cap
  are closed immediately. A client has **30 s** to finish the SSH handshake.
  There is **no idle timeout** — quiet `tmux`/agent sessions stay open — but
  accepted sockets carry TCP keepalive so a vanished peer is detected.

## Resource budgets

`--limit-cpus`, `--limit-memory-mib`, and `--limit-disk-mib` are **operator
budgets** (default `0` = unlimited). Independently, node capacity is
host-derived: the server advertises the host's real CPU and RAM. An apply that
would exceed either the budget or the host's capacity is **refused up front**
(with a breakdown) instead of sitting `Pending`.

A `Failed`/`Stopped` instance keeps reserving its CPU/RAM as long as its
`restart` policy will bring it back (`always` / `on-failure` /
`unless-stopped`); only `restart: no` releases capacity. `mc2 status` and
`GET /v1/status` report host CPU/RAM/disk, the configured limits, MC2's
reserved CPU/RAM from instance specs, and its measured disk usage.

## Privileged `expose` ports (Linux)

Host ports are always bound on `127.0.0.1`. On Linux, an **`expose` port below
1024** is refused at apply unless the server can bind it — a non-root process
needs `CAP_NET_BIND_SERVICE`:

```bash
sudo setcap cap_net_bind_service=+ep "$(command -v mc2)"
# or, under systemd: AmbientCapabilities=CAP_NET_BIND_SERVICE
```

The error names the port and both remedies, including lowering
`net.ipv4.ip_unprivileged_port_start`. Automatically allocated published
ports come from `10000–65535`; a fixed `published:` port below 1024 needs the
same permission.

## Public hostname

`--public-hostname` publishes the **control plane itself** through the ingress
catalog, so remote clients reach the API over TLS through Traefik
(`--public-tls-cert-resolver`, default `le`). Both values are validated at
startup. This needs `--ingress-config-dir` to point at the same directory your
Traefik file provider reads. It is refused together with `--no-auth`.

## Observability

- **Health:** `GET /health` (public, above) and `GET /v1/status` / `mc2 status`
  (authenticated, richer).
- **OTLP metrics:** set `MC2_OTLP_ENDPOINT` (or `OTEL_EXPORTER_OTLP_ENDPOINT`)
  before boot; the server exports `mc2.server.*`, `mc2.node.*`, and
  `mc2.instance.*`. Restart to pick up a change. See
  [Observability](/documentation/concepts/observability).

## Key behaviors

- **The data dir is the state.** Back up `mc2.db` + `secrets.key` together;
  don't hand-edit them.
- **Restart-safe.** Reconcile is idempotent; a restart adopts the microVMs
  it owns and converges again with no operator action. Sandboxes owned by
  another install (another data dir) are never touched, even if their names
  collide — the colliding instance is reported `Failed` instead.
- **`--no-auth` is per start and lab-only.** The token still exists in the
  store; auth is merely skipped for that process.
- **`--volume-dir` defaults inside the data dir**, so `--data-dir /srv/mc2`
  keeps volumes under `/srv/mc2/volumes` too.
