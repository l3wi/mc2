---
title: Open SSH
description: SSH into a microVM with your own key — directly on the server, or through a Traefik TCP route.
---

**You will learn:** register an SSH key, give a service an SSH endpoint,
connect to it, change it per instance, and route it through Traefik.

**Prerequisites:** [Add secrets](/documentation/guides/add-secrets) (or any
earlier guide) and an SSH key pair. For the Traefik part, the server and
Traefik set up as in [Publish with ingress](/documentation/guides/publish-with-ingress).

MC2's SSH is served by the host, not by an `sshd` inside the guest: the
microVM image needs nothing extra.

```text
 ssh -p 2222 ──► 127.0.0.1:2222 (MC2, on the host) ──► shell in microVM
 ssh -p 2200 ──► Traefik :2200 ──► 127.0.0.1:2222 ──► shell in microVM
```

<Steps>

<Step title="Register your key">

```bash
mc2 ssh add-key developer --file ~/.ssh/id_ed25519.pub
mc2 ssh keys
```

Keys are stored on the server under a name (`developer`); stacks refer to
that name.

</Step>

<Step title="Enable SSH on a service">

Save this as `ssh.yaml`:

```yaml
services:
  dev:
    image: alpine:3.20
    ssh:
      enabled: true
      port: 2222
      authorizedKeys: [developer]
```

```bash
mc2 up -f ssh.yaml
mc2 ssh ls
```

```text
│ REF       ┆ INSTANCE     ┆ PHASE ┆ NODE        ┆ BIND:PORT      │
│ ssh/dev/0 ┆ 65236a2f-... ┆ Open  ┆ k762.hs.net ┆ 127.0.0.1:2222 │
```

Wait until the endpoint shows `Open`. Without `port`, MC2 picks a free one
(`mc2 ssh ls` shows it).

</Step>

<Step title="Connect">

```bash
ssh -p 2222 root@127.0.0.1 hostname
# ssh--dev--0
```

The listener binds the server's loopback by default, so connect from the
server itself, through an SSH tunnel, or via Traefik (below).

</Step>

<Step title="Change SSH for one instance">

```bash
mc2 ssh close ssh/dev/0                                  # stop the endpoint
mc2 ssh open ssh/dev/0 --key developer --port 2223        # reopen elsewhere
mc2 ssh show ssh/dev/0
ssh -p 2223 root@127.0.0.1 hostname
```

`open` and `close` set a per-instance **override** that takes precedence over
the stack file — including a later `mc2 up`. The CLI has no command to drop
the override; to return the instance to its YAML settings, call the API:
`DELETE /v1/instances/<id>/ssh` (see
[REST API: Secrets & SSH](/references/api/secrets-ssh)).

</Step>

<Step title="Route it through Traefik">

A TCP route needs a **fixed** `ssh.port`. Add an ingress block to `ssh.yaml`:

```yaml
ingress:
  tcp:
    - name: dev-ssh
      entryPoint: ssh
      service: dev
```

and an `ssh` entry point to your Traefik static config:

```yaml
entryPoints:
  ssh:
    address: ":2200"
```

```bash
mc2 up -f ssh.yaml
ssh -p 2200 root@127.0.0.1 hostname      # through Traefik
# ssh--dev--0
```

From another machine, use `ssh -p 2200 root@<server>` and allow inbound TCP
2200 on the server. MC2 writes the route as a `HostSNI(*)` TCP router, so
the entry point serves one SSH backend.

</Step>

<Step title="Clean up">

```bash
mc2 down ssh
mc2 ssh rm-key developer
```

</Step>

</Steps>

## Key behaviors

- **Keys are server-wide.** `authorizedKeys` lists key names; an empty list
  (or `ssh: true`) lets every registered key in.
- **Loopback by default.** `ssh.bind` is `127.0.0.1`; change it deliberately.
- **Session limits, no idle timeout.** `--max-ssh-sessions` (64) and
  `--max-ssh-sessions-per-listener` (16) cap connections, and a client has
  30 s to finish the handshake. Idle sessions (a quiet `tmux`) stay open.
- **SFTP is on by default** (`ssh.sftp: true`).
