---
title: Change a running stack
description: Re-apply, update, break, and shrink the quickstart's stack to see exactly what mc2 up does.
---

**You will learn:** what `mc2 up` does when a stack is already running — an
unchanged file, a changed file, an invalid file, and a file with a service
removed.

**Prerequisites:** the [Quickstart](/documentation/quickstart): a running
server, a CLI context, and `hello.yaml`. If you ran `mc2 down hello` at the
end, run `mc2 up -f hello.yaml` again first.

```text
            mc2 up -f hello.yaml
                     │
     ┌──────────┬────┴─────┬───────────────┐
 unchanged   changed     invalid      service removed
     │          │           │               │
 nothing    recreate     rejected,      its instances
 happens    that VM      nothing        deleted
                         changes
```

<Steps>

<Step title="Preview what the server will receive">

```bash
mc2 config -f hello.yaml
```

This validates the file and prints it with defaults filled in (here, the
`name: hello` taken from the file name) without applying anything. It
catches mistakes before they reach the server.

</Step>

<Step title="Re-apply the unchanged file">

```bash
mc2 up -f hello.yaml
mc2 ps --stack hello
```

Nothing happens: the instance keeps its ID and stays `Running`. Applying
the same file twice is always safe.

</Step>

<Step title="Change something">

Edit `hello.yaml` so the page text comes from an environment variable:

```yaml
services:
  web:
    image: python:3.12-alpine
    environment:
      GREETING: hello again
    command: ["/bin/sh", "-c", "mkdir -p /tmp/www && echo \"$GREETING\" > /tmp/www/index.html && cd /tmp/www && exec python -m http.server 8000"]
    ports:
      - "18091:8000"
```

```bash
mc2 up -f hello.yaml
```

The environment is fixed when a microVM is created, so the next reconcile
pass **recreates** it: same instance, new VM. Wait a few seconds, then:

```bash
curl http://127.0.0.1:18091/
# hello again
```

</Step>

<Step title="Try an invalid change">

Add `cpus: 0.5` under `web:` and apply:

```bash
mc2 up -f hello.yaml
```

```text
Error: up failed: 400 Bad Request: invalid stack YAML: services.web.cpus:
cpus must be a whole number of vCPUs (got 0.5): each microVM gets whole
vCPUs — use 1 at line 4 column 11
```

The apply is rejected as a whole and the running stack is untouched —
`curl` still answers `hello again`. Remove the `cpus` line again.

</Step>

<Step title="Add a service, then remove it">

Append a second service to `hello.yaml`:

```yaml
  worker:
    image: alpine:3.20
```

```bash
mc2 up -f hello.yaml
mc2 ps --stack hello     # web/0 and worker/0, both Running
```

Now delete those two lines and apply again:

```bash
mc2 up -f hello.yaml
mc2 ps --stack hello     # only web/0
```

The file is the **whole** desired state: a service missing from it is
removed, just like lowering `scale` removes replicas.

</Step>

<Step title="Tear it down">

```bash
mc2 down hello
```

`down` removes the stack's instances and its definition (`rm` is an alias).
Running it again returns `404 stack not found`. Stacks with volumes keep them
unless you pass `--volumes` — see
[Tear down & clean up](/documentation/guides/tear-down-and-clean-up).

</Step>

</Steps>

## What you learned

- `mc2 config` validates without applying.
- Re-applying an unchanged file does nothing; a change recreates only the
  affected microVMs.
- An invalid file changes nothing at all.
- Removing a service from the file removes it from the server.
