---
title: Add secrets
description: Store a value once, inject it into services, and scope it to allowlisted hosts.
---

**You will learn:** create a server-wide secret, reference it from a stack,
and understand the fail-closed `allowHosts` behavior.

**Prerequisites:** [Run your first stack](/documentation/guides/run-your-first-stack).
This guide mirrors `examples/02-secrets`.

<Callout type="warning" title="Lab verification">
  The secrets example verifies configuration and agent sync but does not yet
  provide a complete guest-side command proving the injected value.
</Callout>

## Store the value once

```bash
mc2 secret set SMOKE_TOKEN --value 'lab-only-token'
```

Secrets are a **server-wide** store — set once, referenceable by name from
any stack. The value is encrypted at rest and **never echoed back**:

```bash
mc2 secret ls        # names/metadata only
mc2 secret rm SMOKE_TOKEN
```

## Reference it from a stack

```yaml
name: smoke-secrets
services:
  web:
    image: alpine:3.20
    secrets:
      - name: SMOKE_TOKEN
        env: API_TOKEN
        allowHosts:
          - api.example.com
```

## Bring it up

```bash
mc2 up -f examples/02-secrets/stack.yaml
mc2 ps
```

## What you get vs what you don't

- The guest does **not** receive the raw value. It sees a placeholder
  (`$MSB_API_TOKEN`).
- The sandbox's egress proxy enables TLS interception; the **real value is
  attached only when the guest connects to an allowlisted host**
  (`api.example.com`).
- `allowHosts` must be non-empty — injection **fails closed** otherwise.

## Rotate a secret

```bash
mc2 secret set SMOKE_TOKEN --value 'new-value'
mc2 up -f examples/02-secrets/stack.yaml   # re-apply → sandbox recreated
```

## Precedence gotcha

An explicit `environment:` entry **overrides** a colliding `secrets[].env` —
the secret is dropped (never decrypted) and a warning is logged. If you see
an env var not being injected, check for a collision.

## What you learned

- One encrypted store, shared server-wide.
- Reference by name in the stack; scope to hosts with `allowHosts`.
- Values never leave the host except as a per-connection injection.
