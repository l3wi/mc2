---
title: Add secrets
description: Store a credential on the server and use it from a guest that only ever sees a placeholder.
---

**You will learn:** store a secret, give a service access to it for one
host, and see for yourself that the guest holds a placeholder while the
allowed host receives the real value.

**Prerequisites:** [Use persistent volumes](/documentation/guides/use-persistent-volumes)
(or any earlier guide), and outbound internet access from the server — the
lab uses [httpbin.org](https://httpbin.org), which echoes requests back.

<Steps>

<Step title="Store the secret">

```bash
printf 'lab-only-token' | mc2 secret set DEMO_TOKEN
mc2 secret ls
```

```text
│ NAME       ┆ UPDATED                          │
│ DEMO_TOKEN ┆ 2026-09-28T20:01:45.314415+00:00 │
```

The value is read from stdin (or `--value`, or `MC2_SECRET_VALUE`) and
stored encrypted. Nothing ever lists it back.

</Step>

<Step title="Reference it from a stack">

Save this as `secrets.yaml`:

```yaml
services:
  app:
    image: alpine:3.20
    secrets:
      - name: DEMO_TOKEN     # the stored secret
        env: API_TOKEN       # the variable in the guest
        allowHosts:
          - httpbin.org      # the only host that may receive the value
```

```bash
mc2 up -f secrets.yaml
mc2 ps --stack secrets     # wait for app/0 to be Running
```

</Step>

<Step title="Look from inside the guest">

```bash
mc2 exec secrets/app/0 /bin/sh -c 'echo "$API_TOKEN"'
# $MSB_API_TOKEN
```

The guest's variable holds a placeholder, not the token.

</Step>

<Step title="Use it against the allowed host">

```bash
mc2 exec secrets/app/0 /bin/sh -c \
  'wget -qO- --header "Authorization: Bearer $API_TOKEN" https://httpbin.org/headers'
```

```text
    "Authorization": "Bearer lab-only-token",
```

The request left the guest carrying the placeholder; the microVM's outbound
proxy swapped in the real value because the host is in `allowHosts`.
httpbin echoing it back also shows the flip side: an allowed host **can**
return the value to the guest, so only allow hosts you trust with it.

</Step>

<Step title="Try another host">

```bash
mc2 exec secrets/app/0 /bin/sh -c \
  'wget -qO- --header "Authorization: Bearer $API_TOKEN" https://postman-echo.com/headers'
# wget: error getting response: Invalid argument
```

A request carrying the placeholder to any host outside `allowHosts` is
refused. The same request without the placeholder goes through normally.

</Step>

<Step title="Clean up">

```bash
mc2 down secrets
mc2 secret rm DEMO_TOKEN
```

Remove the stack **before** the secret: deleting a secret that a running
service references marks that service `Failed`, but its existing microVM
keeps the old value.

</Step>

</Steps>

```text
 mc2 secret set ──► encrypted in mc2.db
                          │  each reconcile pass
                          ▼
 guest: API_TOKEN=$MSB_API_TOKEN
 guest ──TLS──► httpbin.org      ──► proxy inserts the real value
 guest ──TLS──► anything else    ──► request with the placeholder refused
```

## Key behaviors

- **Secrets are server-wide.** Any stack can reference `DEMO_TOKEN` by name;
  there's no per-stack declaration.
- **Rotation is automatic.** `mc2 secret set DEMO_TOKEN` with a new value
  recreates every instance using it on the next pass — no re-apply.
- **A missing secret fails only its consumers**, with a message naming it.
- **`environment:` wins on a name clash.** If `environment` also sets
  `API_TOKEN`, the secret is dropped for that service and a warning is
  logged.
- **Back up `secrets.key` with `mc2.db`.** Without the key, stored secrets
  can't be decrypted and the server won't start. See
  [Secrets](/documentation/concepts/secrets) for this and the runtime's own
  plaintext copy.
