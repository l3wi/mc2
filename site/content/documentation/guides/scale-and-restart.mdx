title: Scale & restart
description: Run several replicas with their own host ports, and have MC2 replace one when it stops serving.
---

**You will learn:** run a service as three replicas, reach each one on its
own host port, and make MC2 replace a replica whose server has died.

**Prerequisites:** [Change a running stack](/documentation/guides/run-your-first-stack).

## The stack

Save this as `shop.yaml`:

```yaml
services:
  web:
    image: python:3.12-alpine
    scale: 3
    restart: on-failure
    command: ["python", "-m", "http.server", "8000"]
    ports:
      - "18080:8000"
    healthcheck:
      test: ["CMD", "wget", "-q", "-O", "/dev/null", "http://127.0.0.1:8000/"]
      interval: 2s
      timeout: 2s
      retries: 2
      start_period: 10s
```

- `scale: 3` — three instances, each its own microVM.
- `restart: on-failure` — replace a replica that crashes or fails its health
  check.
- `healthcheck` — every 2 s, fetch the page from inside the VM. Two failures
  in a row count as a crash; failures in the first 10 s after boot don't
  count, so a slow start isn't punished.

<Steps>

<Step title="Bring it up">

```bash
mc2 up -f shop.yaml
mc2 ps --stack shop
```

Repeat `mc2 ps` until all three replicas are `Running` (the first run
downloads the image).

</Step>

<Step title="Reach each replica">

A fixed host port with `scale: 3` becomes a block of three, one per replica:

```text
 shop/web/0 ──► 127.0.0.1:18080 ──► guest :8000
 shop/web/1 ──► 127.0.0.1:18081 ──► guest :8000
 shop/web/2 ──► 127.0.0.1:18082 ──► guest :8000
```

```bash
for port in 18080 18081 18082; do
  curl -s -o /dev/null -w "$port %{http_code}\n" http://127.0.0.1:$port/
done
# 18080 200
# 18081 200
# 18082 200
```

A target-only port (`"8000"`) would instead get an automatic host port per
replica. Either way, allocations stay the same across re-applies.

</Step>

<Step title="Kill a replica's server">

Stop the Python server inside replica 1:

```bash
mc2 exec shop/web/1 /bin/sh -c '(sleep 1; kill "$(pidof python)") >/dev/null 2>&1 &'
```

(The kill runs in the background so `mc2 exec` returns before the server
dies.) Watch replica 1:

```bash
mc2 ps --stack shop -o json   # or just mc2 ps --stack shop, repeatedly
```

Within a few seconds its health check fails twice, and the replica goes to
`Creating` with a message like `restart backoff 2s`, then back to `Running`.
The other two replicas are untouched throughout.

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:18081/
# 200
```

</Step>

<Step title="Scale down">

Change `scale: 3` to `scale: 2` and apply:

```bash
mc2 up -f shop.yaml
mc2 ps --stack shop     # web/0 and web/1 only
```

The highest ordinal is removed and its host port (18082) is released. The
remaining replicas keep their IDs and ports.

</Step>

<Step title="Clean up">

```bash
mc2 down shop
```

Later guides reuse nearby ports, so tear each guide's stack down when you
finish it.

</Step>

</Steps>

## Why the health check matters

MC2 watches the **microVM**. If the VM stops or crashes, `restart` handles
it. But a server process can die while its VM keeps running — MC2 would still
see `Running`. A health check that exercises the service catches that case,
and a failure past `retries` is treated like a crash.

Repeated restarts wait longer each time — 2 s, 5 s, 15 s, then 30 s — so a
crash loop can't restart on every pass. The wait resets after 60 s of
continuous `Running`.

## Key behaviors

- **Distinct host ports per replica**, with no bookkeeping on your side.
- **Scale down removes the highest ordinals** and frees their ports.
- **A recreate starts from the image.** Files the replica wrote outside a
  volume are gone; see
  [Use persistent volumes](/documentation/guides/use-persistent-volumes).
- **Ingress follows a live replica.** A route targets a healthy `Running`
  replica (or any `Running` one) and that replica's own host port.
