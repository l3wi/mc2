---
title: Use persistent volumes
description: Keep data across microVM recreates and stack teardown, cap its size, and grow it.
---

**You will learn:** mount a named volume, prove its data survives a recreate
and `mc2 down`, see what happens when it fills up, grow it, and delete it.

**Prerequisites:** [Publish with ingress](/documentation/guides/publish-with-ingress)
(or any guide before it — this one only needs a running server).

## The stack

Save this as `vols.yaml`:

```yaml
volumes:
  data:
    kind: dir
    size: 64MiB
services:
  keep:
    image: alpine:3.20
    volumes:
      - name: data
        target: /data
```

`keep` has no `command`, so it runs `sleep infinity` — enough to `exec` into.
The volume is small on purpose, so you can fill it.

<Steps>

<Step title="Write a marker">

```bash
mc2 up -f vols.yaml
mc2 ps --stack vols        # wait for keep/0 to be Running
mc2 exec vols/keep/0 /bin/sh -c 'echo durable > /data/marker.txt && df -h /data'
```

`df` inside the guest shows the 64 MiB cap. On the server, the data is a
plain directory:

```bash
mc2 volume ls
```

```text
│ STACK ┆ VOLUME ┆ SIZE   ┆ USED  ┆ PATH                                  │
│ vols  ┆ data   ┆ 64 MiB ┆ 0 MiB ┆ /home/you/.mc2/volumes/mc2-vols--data │
```

</Step>

<Step title="Recreate the microVM">

Add a label to `keep` (any change to create-time config forces a recreate):

```yaml
  keep:
    image: alpine:3.20
    labels:
      demo: recreated
```

```bash
mc2 up -f vols.yaml
# wait for keep/0 to be Running again, then:
mc2 exec vols/keep/0 cat /data/marker.txt
# durable
```

The microVM and its root disk are new; the volume is the same directory.

</Step>

<Step title="Fill it up">

```bash
mc2 exec vols/keep/0 /bin/sh -c 'dd if=/dev/zero of=/data/big bs=1M count=100'
mc2 exec vols/keep/0 /bin/sh -c 'echo x >> /data/more'
# sh: write error: No space left on device
```

Writes stop at the declared size. Within about a minute (usage is sampled
periodically) MC2 reports it:

```bash
mc2 ps --stack vols
```

```text
│ STACK ┆ SERVICE ┆ ORD ┆ PHASE   ┆ ... ┆ NOTES            ┆ ...
│ vols  ┆ keep    ┆   0 ┆ Running ┆ ... ┆ volume data full ┆ ...
```

`mc2 exec`, `mc2 logs`, and `mc2 ssh open` print the details and the fix
before they run:

```text
vols/keep/0: volume "data" full — 64 MiB of 64 MiB used (mounted at /data).
Writes under /data fail with "No space left on device".
  Fix: raise the size in stack.yaml, then run `mc2 up -f stack.yaml` (data is kept,
  the VM restarts):
    volumes:
      data:
        size: 128MiB
```

</Step>

<Step title="Grow it">

Change `size: 64MiB` to `size: 128MiB`:

```bash
mc2 up -f vols.yaml
# after keep/0 is Running again:
mc2 exec vols/keep/0 /bin/sh -c 'cat /data/marker.txt; df -h /data'
# durable
# ... 128.0M  64.0M  64.0M  50% /data
```

Shrinking below what the volume holds is refused:

```text
Error: up failed: 400 Bad Request: volume "data" already holds 64 MiB;
`size: 32 MiB` is smaller. Free space first or choose at least 64 MiB
```

</Step>

<Step title="Tear down, keep the data">

```bash
mc2 down vols
mc2 volume ls         # still there; SIZE shows "-" with no stack declaring it
mc2 up -f vols.yaml   # bring the stack back
# after keep/0 is Running:
mc2 exec vols/keep/0 cat /data/marker.txt
# durable
```

</Step>

<Step title="Delete it">

```bash
mc2 down vols --volumes
mc2 volume ls
# No volumes.
```

`--volumes` uses the stack's definition to find its volumes, so run it
while the stack exists. After a plain `mc2 down`, re-apply the stack first,
then `down --volumes`.

</Step>

</Steps>

## Key behaviors

- **Volumes live on the server** under `<data-dir>/volumes` (`~/.mc2/volumes`
  by default; `mc2 server --volume-dir` moves them). Back that directory up.
- **`size` is enforced**, default 10 GiB. Growing keeps the data and
  restarts the microVM; shrinking below current use is rejected.
- **Sharing needs care.** MC2 doesn't stop two services (or replicas) from
  mounting the same volume. Each gets the remaining allowance when it starts,
  so together they can exceed `size`; avoid concurrent writers unless your
  application coordinates them.
- **Everything outside a volume is lost on recreate.**
