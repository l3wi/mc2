---
title: Tear down & clean up
description: What mc2 down removes and keeps, how to delete volumes safely, and what outlives every stack.
---

**You will learn:** remove a stack without losing data by accident, delete
its volumes when you mean to, and clean up the things that live outside any
stack.

**Prerequisites:** [Manage a remote server](/documentation/guides/manage-a-remote-server)
(or any earlier guide) and a stack to remove.

## Check before you remove

```bash
mc2 ps --stack <stack>     # its instances
mc2 volume ls              # volumes on the server, with size and path
```

## Choose one command

```bash
mc2 down <stack>             # remove instances and the stack definition
mc2 down <stack> --volumes   # ...and delete the stack's volumes too
```

These are alternatives, not steps. `rm` is an alias for `down`.

| Thing | `mc2 down` | `mc2 down --volumes` |
| --- | --- | --- |
| Instances and their microVMs | removed | removed |
| Stack definition | removed | removed |
| Host ports and exposed-port claims | released | released |
| Volumes | **kept** | deleted |
| Secrets, SSH keys | kept | kept |
| CLI contexts (on your machine) | kept | kept |

```text
 mc2 down shop ────────────► instances, definition gone; volumes kept
                                   │
 mc2 up -f shop.yaml ◄─────────────┘ (volumes reattach with their data)

 mc2 down shop --volumes ──► instances, definition, and volumes gone
```

<Warning title="Deleting volumes later">
  `--volumes` finds volumes through the stack's definition. After a plain
  `mc2 down`, the definition is gone and `mc2 down <stack> --volumes` returns
  `404 stack not found`. To delete retained volumes later, re-apply the stack
  first, then run `mc2 down <stack> --volumes`.
</Warning>

Running `mc2 down` on a stack that no longer exists returns
`404 stack not found: <stack>` — it isn't silently ignored.

## Things that outlive stacks

Secrets and SSH keys are server-wide and never removed with a stack:

```bash
mc2 secret ls      && mc2 secret rm <name>
mc2 ssh keys       && mc2 ssh rm-key <name>
```

Remove a stack **before** the secrets it uses: deleting a referenced secret
marks its consumers `Failed` without clearing the value from their running
microVMs.

Contexts are settings of the CLI on your own machine (`~/.mc2/config.toml`),
not server state.

## Removing everything

To remove MC2 from a machine:

1. `mc2 down <stack> --volumes` for every stack (`mc2 ps` lists them).
2. Stop the server.
3. Delete the data dir (`~/.mc2` by default) — the database, the secrets
   key, and the volume root. Back it up first if there's any chance you'll
   want it.

Stopping the server alone doesn't stop running microVMs; `mc2 down` does.
